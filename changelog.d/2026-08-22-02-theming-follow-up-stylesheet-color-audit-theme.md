- **Theming follow-up: stylesheet color audit + theme-aware highlight-color picker** (this session, 2026-08-22, person-requested: "Prüfe, ob konsequent umgesetzt... gib mir eine Option, eine Highlightfarbe zu wählen, die auf die im Theme festgelegten Farben freigegeben ist"). Audited every CSS rule outside the theme-definition blocks for leftover hardcoded colors — found ~18 (scrollbar thumb, toolbar button hover borders, brand mark, Save/active-chip text, and the highest-impact group: breadcrumb/level-pill/level-badge/log-row-hover/token-chip alpha-tinted borders and backgrounds) still hardcoding the DARK theme's own hex/rgba values regardless of the active theme — invisible on Dark, wrong everywhere else. Fixed with two new vars (`--accent-on` for text-on-accent surfaces, `--border-hover` derived via `color-mix()` from `--border`/`--text-tertiary`) and `color-mix(in srgb, var(--x) N%, transparent)` for the alpha-tinted cases (CSS's only way to apply alpha to a themed `var()` color). The timeline minimap needed no fixes — already fully `fill:var(--level-error)`-etc. from when it was built. Separately, the per-filter-node highlight-color picker (previously theme-independent) gained a "Free"/"Theme" mode toggle: Theme mode restricts its preset swatches to the ACTIVE theme's own `highlightPalette` (the 14 named Catppuccin accent colors per flavor, or a custom theme's own optional array) instead of the generic curated set, so a chosen highlight color is guaranteed to belong to the current theme.

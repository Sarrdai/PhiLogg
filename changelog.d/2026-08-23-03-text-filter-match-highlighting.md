- **Text-filter match highlighting** (this session, 2026-08-23, person-requested alternative implementation of `FEATURE_BACKLOG.md` #13's "why is this row here" popup idea — that entry is deliberately left unchanged, this is a separate feature, not a replacement, German: *"wenn ein Textfilter in der Filterkette aktiv ist, dann möchte ich in dem Filterview... Textabschnitte in den Messages durch eine Markierung hervorheben, wo dieser Match zutrifft"*). Marks the exact substring an active `text` filter node matched, inline in the Filter view's rows and/or the entry-detail panel — see "Text-filter match highlighting" above for the full mechanism. Three-state master setting (Settings → Behavior, `#settingsTextMatchHighlightMode`): off / only the active filter ("last", **default**, no fallback to a text-filter ancestor) / any filter in the active chain ("any"). Two independent "where" toggles (`#settingsTextMatchHighlightRows`/`-Detail`, both default ON), only shown while the master isn't off. Covers wildcard/value-token text filters too (numeric conditions re-checked per occurrence), and highlights within whichever column a target-column-restricted filter actually applies to, not just the message. Runtime-only/derived, no new filter-node field — none of the persistence-carrier gotchas apply. `tests/philogg.regression.test.js` Group 93 (new). 1758 passed, 0 failed.

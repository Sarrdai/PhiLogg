- **Level bar can write into the filter tree** (this session, 2026-08-23, `FEATURE_BACKLOG.md` #10, previously marked "(maybe)" — clarified via two person-decided questions before implementing: trigger mechanism and how multiple active levels are represented). New Settings → Behavior setting, `#settingsLevelFilterTreeMode` — **"auto" (default)**: clicking a level button upserts a real `filterType:"level"` tree node (`value` = array of active level names) at the current position, edited in place while the active node already is one, deleted (undoably) once every level is toggled back off; **"explicit"**: the level bar keeps its exact original tree-independent `state.levelFilter` behavior, plus a new `#btnApplyLevelToTree` ("Add to tree") button, shown only in this mode, that pushes the current selection into the tree on demand. Switching modes clears `state.levelFilter` so it can't silently bleed into the other one. A `"level"` node's array `value` rides the existing generic `value` field through every persistence carrier untouched — only `FILTER_TYPES` needed the new type added. See "Level bar: filter-tree mode" below for the full mechanism. `tests/philogg.regression.test.js` Group 94 (new); eight older groups (4/13/33/52/61a/61b/61d/61e) that click the level bar only incidentally now pin `levelFilterTreeMode = "explicit"` first, since "auto" becoming the default would otherwise silently change what those clicks do. 1804 passed, 0 failed.

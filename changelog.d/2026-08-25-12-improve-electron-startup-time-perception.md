- **Improve Electron startup time perception** (this session, 2026-08-25, `FEATURE_BACKLOG.md` #51, retired). Two independent halves, both `desktop/main.js`-only except the one new setting. **(1)** A splash screen (`createSplash()`) shows immediately on launch — a tiny frameless, always-on-top window loading a self-contained inline `data:` URL (spinner + "Loading PhiLogg…", no new asset file) — while the real `BrowserWindow` now loads with `show: false` and only reveals itself (destroying the splash) on its own `"ready-to-show"` event, the first point Electron guarantees an actual painted frame exists (using `"dom-ready"` instead would just swap one blank window for another). **(2)** A new "Close to system tray" setting (`philogg.html` → Settings → Behavior, `settingsCloseToTray`, plain `localStorage` flag `philogg-close-to-tray`, default **on** — the one toggle in that card defaulting on rather than off, since on is the requested desktop-build default rather than an opt-in change): when on, closing the window (the `X` button, or `quitOnLastFileClose`'s own `window.close()` — both funnel through the same `BrowserWindow` `"close"` event) hides it to a new system-tray icon (`createTray()`, 16px inline SVG data URL, deliberately not run through `electron-builder`'s icon pipeline — see "no app icon yet" below) instead of quitting; right-click offers a real Quit. `main.js` reads the setting back via `executeJavaScript()` on each `"close"` (same "no preload/IPC bridge" tier/mechanism as every other desktop-only toggle) rather than the renderer pushing it proactively. A module-level `isQuitting` flag, set in `app.on("before-quit", ...)`, distinguishes an actual quit from the hide-to-tray interception. `focusWindow()` now also un-hides (not just un-minimizes) the window, so reopening a file or clicking the tray icon while parked in the tray feels instant rather than like a fresh relaunch.

- **Icon swaps, Escape closes Settings, file-selection clarity bugfix, "On open, scroll log to" setting, Font size split into UI scale / Log text size, UI font family setting** (this session, 2026-08-26, person-requested batch). **Icons**: `#btnSettings` now uses a gear/cog SVG instead of the old sun icon; the shared `ICON_PIN` constant (`#btnPinBookmarks`, the sidebar peek toggle, the detail-panel peek toggle) is now a plain thumbtack (circle head + needle) instead of the old map-pin/teardrop outline. **Escape**: the global `Escape` keydown handler now also calls `closeSettingsDialog()`, alongside the popups it already closed. **File-selection clarity bugfix** (person-reported, German: *"Klare Darstellung in welcher Datei man ist, besonders beim neu laden -> sieht aus als wäre die alte und die aktuelle Version selektiert. Hintergrundselektion wird nicht geupdated."*). Root cause: `createFileNode` unconditionally set `state.activeId = node.id` on every call, including each of the N calls `restoreSessionFromCache` makes (once per restored file, via `addFile`) while restoring a session at boot — the tree's `.tree-row.active` background highlight visibly thrashed through every restored file in sequence (verified with a mocked `render()` call-count/activeId trace: with 3 files restored and the persisted-active one NOT the last, the highlight bounced through all 3 before `restoreSessionFromCache`'s own final `s.active` correction snapped it back) before landing on the actually-persisted active file — never two rows genuinely active at once (`renderTree()` always rebuilds the whole tree from scratch, so exactly one row ever carries `.active` on any single render), but a real, visible flicker across the wrong files first. Fixed by gating that assignment on `!sessionRestoreInProgress` (the flag `restoreSessionFromCache` already sets for its whole run) — restore now leaves `state.activeId` untouched until the loop's own single, correct, final assignment; a new `else` branch there also falls back to the first restored file when no active node was persisted at all (previously would have silently stayed on whatever a leftover `createFileNode` call happened to set, now explicit). **"On open, scroll log to" setting** (Settings → Behavior, `#settingsOpenScrollPosition`, `philogg-open-scroll-position`, default `"start"` = unchanged existing behavior): `"end"` sets a one-shot `_openScrollToEnd` flag on a root file node at creation (`createFileNode`/`createQueuedFileNode`), consumed by `renderTable()`'s "no scroll anchor to restore" fallback the first time that file's `currentViewEntries` is actually non-empty — checked *before* `restoreViewAnchor` rather than after: a just-created file's own `getVisibleEntries()` call (from its zero-entries creation render) and its post-parse completion render read the exact same underlying `node.entries` array by reference, so a naive anchor check after `restoreViewAnchor` would find a coincidental "self-match" (the file's own first entry, captured before parsing and matched again after) and silently keep the scroll at the top instead — the flag now short-circuits ahead of that. Since `state.tailFollow` already defaults `true`, landing at the bottom means a live-tailed file continues following from there with no extra wiring. **Font size split** (`FEATURE_BACKLOG.md` #42+44): the old single "Font size" row/`fontScale` (whole-page CSS `zoom`, `philogg-font-scale`) is now "UI scale" — same mechanism, same storage key (no migration needed, still just the whole-UI zoom) — plus a new, independent "Log text size" (`logTextScale`, `philogg-log-text-scale`, defaults to 100 = no extra change on top of UI scale, so upgrading users see no visual difference until they touch either slider). Log text size does NOT reuse `zoom` — nesting a second `zoom` under the log content specifically would throw off `measureMsgWidth`'s column-width math (that function's own comment already documents `offsetWidth` being zoom-invariant only relative to the single root-level zoom it was verified against). Instead it drives a new `--log-text-scale` CSS custom property (`:root`, default `1`), multiplied via `calc()` into the font-size of the actual log/text content rules only — `.col-time`/`.col-delta`/`.level-badge`/`.col-thread`/`.col-loc`/`.col-msg` (main table, reused by the Full/Highlight view's row renderer), `#detailMessage` (entry detail), `#extractTable` (extraction table), `.pair-row-time`/`.pair-row-msg` (Link view) — toolbars/panels/buttons are untouched by it, only by UI scale. **UI font family setting** (`FEATURE_BACKLOG.md` #46, Settings → Appearance, `#settingsUiFontSelect`, `philogg-ui-font`, default `"default"`): a curated list of system-installed font stacks only (`UI_FONT_OPTIONS` — system default, Arial/Helvetica, Georgia, Verdana, Monospace via `var(--font-mono)`) — no `@font-face`, no remote fetches, per the "no dependencies" rule — applied by overriding the `--font-ui` custom property `body` (and most UI chrome) already keys off, same live-apply pattern as the theme setting. `tests/philogg.regression.test.js` Group 111 (new, six sub-groups a–f) covers all of the above: icon shape identity, Escape closing Settings, the restore-thrash fix (mocked render-call trace + final single-`.active`-row assertion) and its no-persisted-active fallback, both scroll-position options plus the one-shot-flag/no-re-trigger-on-later-switch case, UI scale vs. Log text size updating fully independently (including which CSS var/zoom each one leaves untouched), and the UI font select (options exist, none reference anything external, selecting one updates `--font-ui`).

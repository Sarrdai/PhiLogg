- **Electron settings + cache now live in the OS well-known config directory** (this session, 2026-08-26, `FEATURE_BACKLOG.md` #33, retired; person-requested, plan agreed before implementation). `desktop/main.js` gained `app.setName("PhiLogg")` so `app.getPath("userData")` resolves consistently to `~/.config/PhiLogg` (Linux) / `~/Library/Application Support/PhiLogg` (macOS) / `%APPDATA%\PhiLogg` (Windows) in both dev and packaged runs — the IndexedDB cache already lives there automatically once that path is right, no other change needed for it. Settings (`philogg.html`'s `philogg-*` `localStorage` keys) are mirrored into a new plain `settings.json` in the same directory: `desktop/preload.js` hydrates `localStorage` from it (real `setItem` calls, not a method override) before `philogg.html`'s own script runs — the only point early enough for the keys it reads once at top-level parse — while `main.js`'s new `watchSettings()` polls `localStorage` (~1s, same shape as the existing theme-overlay watcher) and writes changes back, with a best-effort flush on window close. The tray (previously only built lazily once "close to tray" fired) is now always created, so its context menu can offer "Open Config Folder" and "Clear Cache" (`session.clearStorageData` + reload) as the reachable UI for both files. `philogg.html` itself is untouched throughout — everything lives in `desktop/`. Not verified live (no display server in this environment, same standing limitation as the rest of `desktop/`) — reasoning checked against Electron's own `app.getPath`/`contextIsolation`/`session.clearStorageData` docs, not guessed.

- **Desktop-only extension of the UI font picker: every OS-installed font, via `font-list`** (this session, 2026-08-26, person-requested follow-up to the UI font family setting below — *"is it possible to add a broader selection based on what the system is capable of, only when the Electron Wrapper is used"*, citing Fira Code/Iosevka). The plain `philogg.html` build still can't enumerate installed fonts (no permission-prompt UI to gate the browser's Local Font Access API, and adding one would break the "no dependencies" static-file rule) — but the desktop wrapper is a Node process with no such restriction, so it can shell out to the OS directly. Added a new `window.philogg.listSystemFonts()` bridge (`desktop/preload.js`) backed by a `philogg:list-system-fonts` IPC handler in `desktop/main.js` that calls the `font-list` npm package (`getFonts()`, wraps `fc-list`/PowerShell/`system_profiler` per platform, no permission dialog needed since it's local Node, not the browser) and caches the result for the process's lifetime; any failure (headless CI, missing binary) just resolves to `[]`. `philogg.html`'s `initUiFont()` now calls this (when present) after applying the curated default, appending every returned name as an `<optgroup>` under `#settingsUiFontSelect` — deduped against the curated stacks' own leading font name (so e.g. "Arial" isn't offered twice) — with each option's value prefixed `sys:` and its stack computed on the fly as `"<name>",<default fallback stack>` (`fontStackForId()`), rather than requiring every system font to be a hardcoded `UI_FONT_OPTIONS` entry. Selecting one persists the `sys:`-prefixed id to `philogg-ui-font` exactly like any curated choice. `desktop/package.json` gained `font-list` as a real dependency (desktop-only, doesn't touch `philogg.html`'s own zero-dependency rule). `tests/philogg.regression.test.js` Group 113 (new, two sub-groups): (a) confirms nothing changes without `window.philogg` (plain build); (b) stubs `listSystemFonts` (via a new `opts.philogg` hook in the shared `withApp()` test helper, applied in `beforeParse` so it's present before the inline script's own `initUiFont()` runs) returning `["Fira Code", "Iosevka", "Arial"]`, and asserts the optgroup appears, "Fira Code" is offered and selectable, "Arial" is NOT duplicated, and the resulting `--font-ui`/localStorage value are correct.

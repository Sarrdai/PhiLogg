- **Format-specific log levels** (this session, 2026-08-26, `FEATURE_BACKLOG.md` #47, retired: *"configurable while setting up a parser (Format Manager), with a definable order, shown in the log-level column instead of forcing the fixed ERROR/WARN/INFO/DEBUG set"*). A `LogFormat` now carries its own ordered `levels` array — any subset of the fixed colored bucket set `ALL_LEVELS` (`ERROR/WARN/INFO/DEBUG/TRACE`), in any order — edited in the Format Manager's format editor as a checkbox + ▲/▼ list (same idiom as the filename-rule list). `OTHER` is never listed: it stays the implicit catch-all, and `levelBucket()`'s prefix cascade is untouched, so what a raw level string buckets into is unchanged; only which buckets get a quick-filter button, and in which order, is now format-driven. A format without the field (every builtin, everything created before this) falls back to the old fixed `ERROR, WARN, INFO, DEBUG` — no visible change for anyone who doesn't touch the setting. With several files open under different formats, `activeLevelOrder()` renders the union of their lists, concatenated in tree order and de-duplicated, and `canonicalLevelOrder()` re-sorts a level filter node's `value` by that same order (names outside it, e.g. `OTHER` from an imported filter, are kept and appended, not dropped). Entries are stamped with their `formatId` at both parse sites (`parseLogTextAsync`, `appendTailText`). `TRACE` could never be a level-bar button before, so it gained the missing `.level-btn.lvl-trace`/`.active.lvl-trace` rules plus a single `--level-trace-on: var(--level-debug-on)` in `:root` (resolves per theme). Saving a format with no level checked is refused; Reset on the builtin default restores its original four.

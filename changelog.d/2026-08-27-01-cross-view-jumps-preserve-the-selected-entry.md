- **Cross-view jumps (double-click, extraction-table jump) preserve the selected entry's on-screen position instead of centering it** (this session, 2026-08-27, person-requested). The tree-click/Alt+Arrow path already kept the selected row at the same screen pixel offset across a view change (`captureViewAnchor`/`restoreViewAnchor`, see below), clamping to the top when there aren't enough rows above to keep the exact offset. Double-click (`revealInHighlightView`) and the extraction table/plot-mark double-click (`jumpToFullLog`) bypassed that mechanism entirely and always hard-centered the target row — `scrollToIndex`/`scrollToHighlightIndex` gained a new `opts.offset` mode (lands the row at a given pixel distance from the viewport top, clamped to 0 the same way `restoreViewAnchor` already relies on) and both jump functions now capture the source row's actual on-screen offset (`captureRowScreenOffset`, via `getBoundingClientRect`) and carry it through `state.scrollTargetOffset`/`state.highlightScrollTargetOffset` to the render that consumes it, falling back to centering only when the source row wasn't on screen to begin with (nothing to preserve). Bookmark-panel jumps (`jumpToEntry`) and the timeline minimap/plot-mark clicks still center — none of them jump from a row with a meaningful "current screen position".

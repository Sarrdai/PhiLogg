- **Electron: F11 and the native window-control fullscreen button are now fully equivalent** (this session, 2026-08-27, person-reported). `F11` previously toggled a custom bounds-resize hack on Windows/Linux (`toggleWindowedFullscreen`, kept separate from real `setFullScreen()` specifically to keep the Window Controls Overlay's minimize/maximize/close buttons visible — real OS fullscreen has no "titlebar area" for Chromium to paint them into), while the native window controls' own maximize/restore button always used real `win.setFullScreen()`. Two different, non-interoperable toggles meant F11 couldn't exit fullscreen entered via the window control and vice versa. `main.js`'s `watchFullscreenToggle` now just calls `win.setFullScreen(!win.isFullScreen())` on F11 on every platform (macOS already did this) — same code path the native control drives, so either trigger can enter or exit what the other started. Trade-off accepted deliberately: the Window Controls Overlay buttons now disappear in fullscreen on Windows/Linux (matching how real OS fullscreen always looks), same as they already do when triggered via the window control. `windowedFullscreenBounds`/`isWindowedFullscreen`/`toggleWindowedFullscreen` and the now-unused `screen` import removed. See `desktop/README.md`'s "Frameless window" section. No regression-suite coverage — `desktop/` has no test harness (jsdom can't drive a real `BrowserWindow`).

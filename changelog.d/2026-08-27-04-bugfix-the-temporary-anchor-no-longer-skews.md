- **Bugfix: the temporary anchor no longer skews EITHER of the timeline minimap's range boxes** (this session, 2026-08-27, person-reported, two rounds). The temp anchor (a foreign entry stitched into the Filtered table for context by `spliceTempAnchor`) was never a real member of the active filter's own result, but both of the minimap's boxes were letting it in anyway. (a) `renderMainView()` fed `renderTimelineMinimap` the POST-splice `currentViewEntries` list, so an anchor sitting far outside the filter's real time span made `updateMinimapFullRange`'s box (`#minimapFullRangeRect`) balloon out to cover it — fixed by capturing `minimapViewEntries` from `getVisibleEntries()` **before** `spliceTempAnchor` runs. (b) That fix alone left the *second* box, `#minimapRenderedRangeRect` (`updateMinimapRenderedRange`/`minimapRenderedSpan`, "what's actually rendered right now"), still stretching to the anchor — reported again by the same person, since that box legitimately sources from `currentViewEntries` (the anchor row really is a rendered DOM row, unlike (a)'s pure bucketing pass). Fixed by having `minimapRenderedSpan` walk its computed start/end index inward past any `_tempAnchor`-flagged row to the nearest real one before converting to a pixel span (returning `null`/hidden in the edge case where only the anchor row is actually in view). See `docs/ui-and-views.md`'s "temporary anchor" section and Group 120 in the regression suite.

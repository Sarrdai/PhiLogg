- **Bugfix: the minimap's selection pin now hides once nothing on screen is actually marked** (this session, 2026-08-27, person-reported, follow-up to the range-box fixes below). `minimapMarkedEntries` used to resolve the selection pin via a plain `entryIndex` lookup, which finds ANY real entry ever selected regardless of whether it's a member of what's currently on screen — so the pin kept pointing at a stale position after e.g. a faded temp anchor's row was removed from the Filtered table, or after switching to a pane/root file that no longer contains the selected entry (even though `state.selectedId`/`state.tempAnchor` still reference it internally for bookkeeping). It now resolves against `currentHighlightViewEntries` while the Full tab is on screen and `currentViewEntries` while the Filtered tab is (both, in Stacked layout), with no `entryIndex` fallback. `scheduleTempAnchorFade` now calls `updateMinimapSelectionMarkers()` itself the instant a faded anchor's row is actually removed (both the animated-collapse branch and the "scrolled out of the rendered window" early return), and `showFhTab`/`applyFhView`'s Stacked branch call it on every tab switch too. See `docs/ui-and-views.md` and Group 121 in the regression suite.

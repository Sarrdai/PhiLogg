- **Regex filter type, and "Create a filter from the plot view"** (this session, 2026-08-27, `FEATURE_BACKLOG.md` #16 and #11, both retired). Two independent Road-to-1.0 items.
  1. **Regex filter type** (#16, per the person's stated refinement — a toggle at the top of the Filter Dialog, not a separate filter type): `#filterRegexCheckbox` ("Interpret input as regex"), first row of `#filterPopup`. When checked, the input is compiled as a real `RegExp` (`compileRegexFilter`, new) instead of the wildcard-token parser — a new `node.isRegex` boolean flag on the SAME `"text"` `filterType` (no new filter type; `getEntries`'s `"text"` branch, `textFilterMatches`, and `evaluateLiveMatch` all check it first, before the existing wildcard/plain-substring paths). An invalid regex degrades gracefully everywhere: `getEntries` returns an empty result, the popup shows an inline `--level-error` "Invalid regex" state (mirroring the existing "Invalid pattern" state) and refuses to submit — never a thrown exception. Case-sensitivity and column-restriction stay fully available and visible in regex mode (they're generic "text"-filter options, orthogonal to how the pattern is compiled); only the wildcard-token-specific UI — the `[float]`/`[int]`/… insert chips (`#filterTokenChips`) and the live pattern preview (a wildcard-only concept, capture-group highlighting) — hides while regex mode is on, and the Extract button stays disabled (a raw regex has no `[value:...]` placeholder vocabulary to build columns from). Threaded through every persistence carrier per CLAUDE.md's "Known gotchas": `cloneSubtree`, `snapshotSubtree`/`restoreSubtree`, the field-edit-undo `captureNodeFields`/`applyNodeFields` carrier (a 4th carrier alongside the three CLAUDE.md names explicitly, since in-place filter edits use it too), `serializeFilterBranch`/`importFilterJson`, `serializeFilterTreeForCache`/`materializeCachedFilters` — same 6-touch-point pattern `caseSensitive`/`columns` already established, `isRegex` just rides alongside each one.
  2. **"Create a filter from the plot view"** (#11, resolving its own stated open question by implementing BOTH options rather than picking one): two new toolbar buttons in the Plot tab's `#plotZoomBar` (next to the existing zoom controls) — **"Filter: time range"** (`#plotFilterTimeRangeBtn`) creates a `"timerange"` filter (the existing, generic time-filter node type — see "Time filters" in `docs/filters.md`) spanning the min/max timestamp of whatever's currently visible in the plot; **"Filter: these entries"** (`#plotFilterEntriesBtn`) creates a new `"idset"` filter matching EXACTLY those entries. "Currently visible" means the Plot tab's own zoomed/panned viewport (`plotLastRender`'s `xDomainMin`/`xDomainMax` — the home/un-zoomed view when no zoom is active, not always "the whole extraction"), read via a new `getPlotViewportEntries()` that derives each row's on-screen X position the exact same way `renderPlotChart` itself does (bar: row-index slot center; line/scatter: the X column's own parsed value) so it can never disagree with what's actually drawn. **`idset`** (new `filterType`, added to `FILTER_TYPES`): `node.value` is a plain array of entry ids, matched via a `Set` in a new `getEntries` branch — the same "second, pre-computed, non-parent-derived source of truth" shape `"timerange"`/`"bookmarks"` already use, chosen (over, say, reusing `"bookmarks"` or inventing an ad-hoc selection mechanism) because it's generic enough for the exact-entry-set case explicitly asked for in the backlog item's part (b), without dragging in `state.bookmarks`' own global, singleton semantics. Needed **no new persistence-carrier code**: like `"timerange"`, its value rides the existing generic `value` field every carrier already copies/serializes for every filter type — verified directly (not just assumed) via a real `cloneSubtree` copy/paste round trip in the new test group. An empty viewport (nothing currently visible — a zoomed-out-of-data-range or gap case) shows a toast and creates nothing, rather than a broken empty filter. See "Filter popup" in `docs/filters.md` and "Plot zoom/pan" in `docs/extraction-and-plotting.md` (both updated in place). `tests/philogg.regression.test.js`: new **Group 122** (regex — `getEntries` semantics including case-sensitivity/column-restriction/invalid-pattern, the popup's UI toggle hiding wildcard-only elements while keeping the rest, live-match/inline-error states, submit-blocks-on-invalid, and all persistence carriers) and **Group 123** (`idset`'s `getEntries` branch + copy/paste round trip, both new plot-toolbar buttons under a home view and a real zoom, and the empty-viewport no-op case). 2373 passed, 0 failed.

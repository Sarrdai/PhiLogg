- **Plot config now persists per extraction node** (this session, 2026-08-28, person-requested — *"Die Plots sollen ihren Zustand behalten... Auch wenn ich einen Extraction Knoten kopiere, möchte ich das er den gleichen Plot erzeugt."*). Previously the whole plot definition (chart type, axes, color-by, axis-equal, ranges) lived in one shared global reset to defaults on every node switch — including a switch back to the SAME node, so leaving the Plot tab and returning showed a blank plot again, and copying an extraction node never carried its plot along. `plotConfig` now lives on the node itself (`node.plotConfig`, extract-only, created lazily), swapped in by the renamed `loadPlotConfigForNode()` on every genuine node switch — the zoom/pan/rotation viewport still resets (that's "what you're looking at right now," not the plot's definition), but the actual plot setup doesn't. Threaded through all four persistence carriers per CLAUDE.md's gotcha: `cloneSubtree`, `snapshotSubtree`/`restoreSubtree`, `serializeFilterBranch`/`importFilterJson`, `serializeFilterTreeForCache`/`materializeCachedFilters` — the two import paths run incoming values through a new `sanitizePlotConfig()` rather than trusting them directly, since a filter file or cache entry could be hand-edited or foreign. See "Plot config persists per extraction node" in `docs/extraction-and-plotting.md`. `tests/philogg.regression.test.js`: new **Group 126** — leave/return reproduces the same plot, copy reproduces the same plot as an independent deep copy, undo restores it, save/load and session-cache round trips carry it, and `sanitizePlotConfig` rejects a corrupt/foreign value.

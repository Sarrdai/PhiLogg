Now mirrors `loadFileDescriptors`' own multi-file-open shape: a first pass creates a `createQueuedFileNode` placeholder for every restored file, in order, with one `render()`; a second pass activates and parses each one in turn, via a new `existingNode` 5th parameter on `addFile` (mirroring the one `loadOneFileIntoTree` already had). Required a matching fix to `activateQueuedFileNode`, which unconditionally set `state.activeId` — now guarded by `sessionRestoreInProgress`, the same guard `createFileNode` already carries, so routing restore through it doesn't reintroduce the old activeId-thrashing bug through a new call path.

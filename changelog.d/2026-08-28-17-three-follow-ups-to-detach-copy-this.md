- **Three follow-ups to "Detach copy", this session, person-requested.**
  1. **`linkedId` dependency highlight.** Selecting an `and`/`or`/`link` node now highlights its `linkedId` target elsewhere in the tree (`.dep-target`), and selecting a node that's pointed at BY another node's `linkedId` highlights that other node back (`.dep-user`) — `computeLinkedDependencyHighlight()`, once per `renderTree()`. Neither class ever appears on a squash-group's display node, since it no longer has a live cross-tree dependency once detached.
  2. **Cross-file Copy/Cut/drag now reconstructs instead of leaving `linkedId` pointing into the original file.** `pasteClipboard`/`moveFilterNodeWithUndo` (the shared choke point Cut+Paste and real drag-and-drop both funnel through) compare source/destination root files; same-file behavior is unchanged, but a cross-file target now routes through `importBranchAt` (the Save/Load rebuild step, without the JSON round trip) instead of `cloneSubtree`/a plain reparent. A squash group can now move across files too — cross-file reconstruction never reassigns `parentId` in place, so the same-file "would silently detach the visible node from its hidden chain" risk doesn't apply. `moveFilterNodeWithUndo` now returns the id the node ends up under (still `nodeId` for a same-file move, a fresh id for cross-file) — both call sites updated to use it instead of assuming the original id survived.
  3. **A squashed group now stays collapsed through Save/Load JSON / the reusable library** (previously it silently unpacked back to plain visible nodes on import). `serializeFilterBranch` emits `squashGroupRef` (the ref number of the group's one visible member — `squashGroup` is an opaque tag, not a node, so it can't ride the `linkedRef` scheme directly) alongside `hiddenInTree`/`squashExpanded`; `materializeSerializedRoots` resolves it in a third deferred pass, reusing the freshly materialized display member's own id as the group's new tag. New manual **expand/collapse chevron** (`toggleSquashGroupExpanded`) on every squash-group row lets a person see the hidden chain on demand — flips `squashExpanded` on every member of the group at once, purely a display preference (no undo entry, no cache invalidation).

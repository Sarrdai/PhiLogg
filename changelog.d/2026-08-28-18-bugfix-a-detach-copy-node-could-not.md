- **Bugfix: a "Detach copy" node could not be dragged/Cut-pasted anywhere at all** (this session, person-reported — *"detached Filter kann ich nicht verschieben"*). The previous session's fix flatly blocked any same-file move of a squash group's visible node, reasoning that reparenting it in place would decouple it from its own private hidden ancestor chain — true, but the fix was wrong: the actual risk is reparenting the *display* node itself, not moving the group at all. `moveFilterNodeWithUndo` now detects this case and calls a new `moveSquashGroupWithUndo`, which moves every **top-level member** of the group (the ones already sitting directly under the file) to the drop target together, as one compound `"moveGroup"` undo/redo action — the display node's own `parentId` never changes, only where the group's top-level roots are filed. Dragging, Cut+Paste, and the context menu's "Cut" (re-enabled — it had been dropped for the same now-obsolete reason) all work on a detached filter exactly like on any other node. See "Squash / Detach copy" in `docs/filters.md`. `tests/philogg.regression.test.js`: Group 128's own move-related assertion rewritten to verify a real reparent (drag onto a different target moves the group, undo restores it) instead of asserting the old refusal. 2552 passed, 0 failed.

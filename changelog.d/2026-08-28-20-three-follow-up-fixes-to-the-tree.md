- **Three follow-up fixes to the tree row layout rework, same session, person-reported from a screenshot.**
  1. **"Icon" indicator mode still showed the TXT/LNK/... badge too** (only "Type abbreviation" mode looked right). The separate `.tree-type-tag` badge is gone outright now in both modes — the type is stated exactly once, always at the icon's own position (glyph in "Icon" mode, abbreviation text in "Type abbreviation" mode).
  2. **The row-count percentage bar looked identical on every row** — a filter typically keeps well under 10% of its parent's rows, and a plain linear `fraction*100` width puts every realistic value within a pixel or two of "empty" at this bar's size. `.tree-pct-fill`'s width now uses `Math.sqrt(fraction)*100` with a small minimum for any nonzero fraction, so everyday differences (0.4% vs. 13% vs. 100%) actually read apart at a glance; the tooltip still shows the real percentage.
  3. **Expanding a "Detach copy" node's box left the display row floating on top, showing only its ancestors below** — not what "show the whole state" meant. `renderNodeOrGroup` (new — the one caller-side decision point every "render this child" call site now goes through) detects a `hiddenInTree` child whose group is expanded and replaces its WHOLE slot with the box (built once per group, not once per top-level member) instead of `renderNode` rendering a separate row for it; the display node itself now renders INSIDE the box too (`forceVisible`), as the last real row in its own chain, so the box is the group's one complete, non-duplicated picture. `flattenTreeIds()` mirrors the same box-detection so arrow-key nav still reaches every member. Rows inside the box stay non-draggable, and moving/deleting ANY group member (not just the display) now correctly operates on the whole group rather than risking an in-place reparent of just that one member.

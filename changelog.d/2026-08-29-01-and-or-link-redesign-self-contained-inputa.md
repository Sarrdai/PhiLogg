- **AND/OR/LINK redesign: self-contained `inputA`/`inputB` inputs, replacing the `linkedId`/squash-box model** (this session, 2026-08-29). Supersedes and removes the entire previous, never-merged squash-box session below ("Detach copy", `linkedId` dependency highlighting, cross-file reconstruction on move) — none of that work had reached `main`, so nothing here is a migration; old fields/formats are simply deleted, no backward-compat shims.
  - **Core data model**: `and`/`or`/`link` nodes now carry two fixed, explicit input references, `node.inputA`/`node.inputB` (ids of other filter nodes), read directly by `getEntries()`. `node.parentId` is now purely tree display position for these three types — it has zero bearing on the result. `createAndOrNode`/`createLinkNode` always place the new node as a fresh top-level child of the two inputs' shared root file; from there it moves anywhere like any other node, changing only `parentId`.
  - **No cycle guard needed for ordinary moves any more** — `wouldCreateLinkedCycle`/`subtreeHasLinkedCycle` are gone, since `parentId` no longer interacts with the node's own logic. `getEntries()` instead guards against a genuine (only reachable via a hand-edited file) `inputA`/`inputB` cycle with a "currently resolving" set, degrading to an empty result rather than recursing forever.
  - **Cross-file copy/cut/paste/drag no longer needs special-casing** — `importBranchAt` and the cross-file-detection branch in `pasteClipboard`/`moveFilterNodeWithUndo` are gone; ordinary `cloneSubtree`/`moveNode` already work correctly regardless of file boundaries once inputs are self-contained id references.
  - **New "Unpack" context-menu action** (any `and`/`or`/`link` node): replaces it in place with its two inputs (cloned in as real, visible siblings) plus a fresh combiner explicitly wired to reference them, at the same tree position — a no-op on the filter's own result, meant as a stand-in for inline input-editing (not built this pass — see FEATURE_BACKLOG.md).
  - **New export/library prompt**: saving an `and`/`or`/`link` node (or a subtree containing one) to a `.json` file or the reusable library now asks "Include source filters used by combined nodes?" — off (default) exports only the node's own chain, with unresolved inputs marked `inputAMissing`/`inputBMissing` at export time and `node.inputBroken` at import time (surfaced with a visible highlight, never silently dropped); on additionally pulls in each input's own ancestor chain as extra roots.
  - **Removed entirely** (grew out of the abandoned squash-box design): `detachFilterChain` ("Detach copy"), `node.hiddenInTree`/`node.squashGroup`/`node.squashExpanded` and every function reading/writing them (`renderSquashGroupBox`, `renderNodeOrGroup`, `moveSquashGroupWithUndo`, `toggleSquashGroupExpanded`, `squashGroupTopLevelMembers`, `squashGroupDisplayId`), the `"deleteGroup"`/`"moveGroup"` undo/redo kinds, `computeLinkedDependencyHighlight` and the `.dep-target`/`.dep-user` tree-row classes, and the `.tree-squash-box`/`.tree-squash-divider` CSS.
  - **Kept from the previous (never-merged) session**, since they're independent tree-UI improvements: tree row indentation (`8 + depth*18`), generic collapse/expand for any node with real children, the Settings → Behavior "Tree row type indicator" setting, the row-count percentage bar's removal, extract nodes' highlight-colour swatch, the tree context menu's "Info" submenu, and the `textFilterMatches()` wildcard-as-text bugfix (matches `e.message`, not `e.raw`).

- **Full code-review pass over the self-contained filter architecture: five defects fixed, documentation re-synced to the current state** (this session, 2026-08-30). Requested as a review of the whole baked-condition rework now that it has settled, looking for bugs and performance problems and checking that the docs still describe what is actually implemented. All five defects were found by reading the baked model against its persistence carriers and its hot paths, not from a person report, and each was reproduced in jsdom before being fixed.
  1. **`node.formatId` was dropped by the delete-file undo round trip.** `snapshotSubtree`'s file branch copied `entries`/`cacheKey`/`merged`/`tail` but not `formatId`, and `restoreSubtree` didn't restore it. Removing a file parsed under a custom format and undoing left the node with no `formatId`, which silently reverted it to the builtin default in three places: the level bar's button list (`formatLevels`), tail parsing of newly appended lines (`appendTailText`), and the session cache's reparse on the next reload (`persistFileNode` wrote `formatId: null`). Both carriers now thread `formatId` (and `folderId`, which is unreachable today only because `deleteFilterNodeWithUndo` routes folder-owned files to `closeFolderFile` first).
  2. **`addRowsToSelectionFilter` mutated `node.value` in place.** `cloneSubtree`, `snapshotSubtree` and `captureNodeFields` all copy `value` by reference — harmless for the primitive shapes, aliasing for the array/object ones — so pushing into an `idset` selection filter's array also grew every copy/pasted duplicate of that node, and retroactively rewrote the undo stack's own "before" capture. It now replaces the array wholesale (`node.value = node.value.concat(added)`), the same immutable-value convention `"timerange"` already followed. The convention is now written down as a gotcha in `CLAUDE.md`/`PROJECT.md` rather than left implicit.
  3. **An `and`/`or`/`link` node with no baked sides threw.** A filter file or library preset written before the `bakedA`/`bakedB` model materializes as a combiner with neither side, and `bakeNodeCondition`/`materializeBakedAsNode` did a bare `JSON.parse(JSON.stringify(undefined))` on it — so combining such a node threw `"undefined" is not valid JSON`, and Unpack threw on reading `undefined.filterType`. Both now go through `cloneBaked`/`hasBakedSides`; Combine and Unpack refuse the node instead (and the Unpack menu entry is withheld for it), and `importFilterJson`'s validation rejects it up front rather than creating a filter that silently matches nothing.
  4. **AND/OR was offered over a `link` node.** A link's result is synthetic pair entries whose ids never appear in a plain entry pool, so `AND(link, anything)` was always empty and `OR(link, anything)` type-mixed — reachable straight from the bulk-action menu, with no indication anything was wrong. New `canBeCombined` predicate: `describeBulkActions` now offers only "Link…" when either selected node is a link, and `createAndOrNode` refuses such a side. Chaining onto a link is unaffected — that goes through `createLinkNode`, whose evaluator does understand pair entries.
  5. **Performance: `buildOrderIndexMap` rebuilt an O(file size) Map on every render.** `getVisibleEntries()` calls it on every `renderTable()` while "pin bookmarks into the Filtered view" is on, and each link recompute calls it again per nested baked hop — every call allocating a fresh `entry.id -> index` Map over the whole root file. It is now memoized on the file node (`file._orderIndexMap`) with a self-validating key (the entries array's identity and length), so rotation and tail append re-derive it automatically and no invalidation call sites are needed; `mergeFiles`' final in-place sort — the one reorder that key can't see — drops it explicitly via `invalidateOrderIndexMap`.

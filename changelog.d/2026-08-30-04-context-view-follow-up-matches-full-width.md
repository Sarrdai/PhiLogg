- **Context view follow-up: matches full width, revealed context indented (not dimmed), binary gap fold with icon-button navigation** (this session, 2026-08-30, person-provided sketch). Feedback on the rework directly above: the visual didn't match the intent yet — a hand-drawn sketch specified full-width, unindented matches; context rows indented but shown at full opacity, not greyed out; two small fold-back icons (top and bottom of a revealed block) sitting in the indent the fold itself creates; a single indented, lightly dimmed placeholder row (an ellipsis icon plus a line count) standing in for a closed gap. Alongside that: the nav chip's buttons were too small/custom and repeated the filter's name for no reason, its position wasn't configurable, and Stacked layout should always start fully expanded.
  1. **Gaps are now binary** — shut, or fully revealed. The earlier partial/step-reveal control (⌃/⌄ chevrons peeling off 25 lines at a time, `CONTEXT_EXPAND_STEP`) is gone entirely; `contextExpansions` changed from a `Map<gapStart, {before, after}>` to a plain `Set<gapStart>`. Nothing needed it once revealed rows stopped competing for readability with the matches around them.
  2. **Revealed context rows are indented, not dimmed.** `.ctx-context` dropped its `opacity:.5` (and the `:hover`/`.selected` exceptions that undid it) for `padding-left:24px` — full readability, no fight with the `.lvl-error`/`.lvl-warn` row tinting the opacity approach was flattening. Applies whether or not the row also carries a highlight-rule colour, since the "never dim a coloured row" special case is now moot (nothing dims at all).
  3. **An open gap costs no extra row.** Previously every gap — open or shut — occupied a `.ctx-gap` strip row (the open ones as their own "collapse" control). Now only a **closed** gap gets a row (`.ctx-gap-placeholder`, indented like a context row, lightly dimmed to read as a stand-in rather than a real line, ellipsis icon plus "*N* lines", the whole row clickable). An **open** run instead gets two small fold-back icons overlaid inside its own first and last row's indent zone (`.ctx-fold-btn.ctx-fold-top`/`.ctx-fold-bottom`, `stopPropagation`'d so clicking one doesn't also select the row underneath it) — collapsible from wherever in the block you're currently reading. A single-row run shows one icon, not two overlapping ones. `contextStrips` now tracks only closed-gap placeholder positions; a new `contextFoldMarks` (index → `{gap, top, bottom}`) tracks the fold icons, contributing no row height at all — `buildContextRowOffsets` itself needed no change, since its contract was always "however many entries are in `contextStrips`", and there are now fewer of those than before in the common (partly-open) case.
  4. **Nav chip buttons resized and the filter name dropped.** `‹`/`›` (and the expand/collapse-all button) were small custom text buttons (9px font, "‹"/"›"/"⌄"/"⌃") with the active filter's name inline. All three are now `ICON_CARET_LEFT`/`RIGHT`/`UP`/`DOWN` icon buttons styled with the exact same `.panel-toggle-btn` class every other small panel-corner control uses (`#sidebarToggle`, `#detailToggle`) — matching an existing element's size literally, rather than inventing a new one. The filter name is gone from the label (it already sits in the breadcrumb right next to the chip); what's left is a bare "*n* / *m*" position readout. New plain outline icons `ICON_CARET_LEFT/RIGHT/UP/DOWN` and `ICON_ELLIPSIS` — deliberately not the existing `ICON_CHEVRON_LEFT/RIGHT/UP/DOWN`, which carry an extra rail/bar specific to "collapse this panel toward that edge of the screen" and would have been the wrong shape for match-navigation or fold buttons. The chip now also hides entirely on a file node (nothing to navigate or fold there) instead of showing an unrelated "whole file · *N* lines" readout.
  5. **New setting: nav chip corner.** Settings → Behavior → "Match navigation position" (`contextNavCorner`, `philogg-context-nav-corner`, one of `top-right` [default, unchanged from before] / `top-left` / `bottom-right` / `bottom-left`), applied via one of four `.corner-*` CSS modifier classes (`applyContextNavCorner()`).
  6. **Stacked layout always seeds fully expanded.** `buildContextView`'s one-time-per-node seeding step now seeds every gap open whenever `fhLayout === "stacked"`, regardless of `contextInitialExpansion` (which continues to govern the Tabs layout's Context tab only). It is a seed like any other, not a standing override: manually shutting a gap in Stacked survives a flip to Tabs and back. Accepted, documented edge case left alone rather than solved: a node already seeded while in Tabs layout (e.g. collapsed, the default) keeps that seed the first time Stacked is opened on it — switching layout alone never re-seeds, only a genuine node change does.

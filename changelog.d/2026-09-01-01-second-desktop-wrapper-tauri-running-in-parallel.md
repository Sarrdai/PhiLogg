- **Second desktop wrapper: Tauri, running in parallel with Electron** (this session, 2026-09-01, person-requested). Asked for a Tauri wrapper alongside the existing Electron one — same feature set, same visuals (rounded corners, shortcuts, buttons in the current theme) — so it can be tested against it and, if it holds up, eventually replace it. New `desktop-tauri/` (Tauri v2 + Rust; `desktop/` is untouched and stays the supported build). Both install side by side: own identifier `com.kleinphilipp.philogg-tauri`, own product name, own config directory `PhiLogg-Tauri/` (a deliberate sibling of Electron's `PhiLogg/`, so comparing the two can't have one clobber the other's settings). `philogg.html` is not modified — same rule as `desktop/`.
  1. **Feature parity in one pass**, each mirroring `desktop/main.js`: the custom `philogg://` scheme (registered *asynchronously*, since a served log is re-read on every tail tick and a sync handler would block the webview thread), `.log` file associations and CLI-argument opening, single instance with the running window reused via `window.philoggLoadUrl`, splash window, tray (Open / Open Config Folder / Clear Cache / Quit), close-to-tray, `settings.json` mirroring, "Open File Location", the system font list, F11 fullscreen, frameless window with rounded corners.
  2. **Window chrome is real DOM, not a native overlay.** Electron gets minimize/maximize/close from Chromium's Window Controls Overlay; Tauri has no equivalent, so `inject.js` appends a three-button block into `philogg.html`'s own `.toolbar-right`, styled purely from the page's existing theme variables. That removes Electron's whole `watchTheme()` accent-polling loop (the buttons *are* themed elements, so nothing can go stale) along with `TITLEBAR_HEIGHT`'s 49px and the `titlebar-area-*` padding reservation (the buttons occupy real layout space). macOS keeps native traffic lights via `TitleBarStyle::Overlay`. The drag region needed rebuilding too: `-webkit-app-region` is inherited by children, `data-tauri-drag-region` is not, so the attribute is stamped on `#toolbar` and every descendant outside a control, re-stamped by a `MutationObserver`.
  3. **A `fetch` shim, because Tauri doesn't expose a real custom scheme everywhere.** What it registers as `philogg` is served as `philogg://localhost/…` on macOS/Linux and `http://philogg.localhost/…` on Windows — neither is the `philogg://local/…` shape `isDesktopLocalUrl()` matches to decide a URL is a tail-able local file. Rather than change `philogg.html`, the page is handed the canonical URL (keeping tail-follow, filename derivation and the context menu working unmodified) and `window.fetch` rewrites that one prefix to whatever the platform actually serves; the protocol handler accepts both shapes.
  4. **One injected script instead of preload + `dom-ready`.** Tauri's `initialization_script` runs before any page script *and* re-runs on every navigation, so the settings hydration, the bridge, the CSS and the DOM work all live in one file that survives the "Clear Cache" reload with no re-injection hook. The settings *read* half got simpler than Electron's synchronous-IPC preload: the values are known on the Rust side at window-creation time, so they are baked in as a JSON literal. Hydration is once per *process* (a nonce in `sessionStorage`), not per load, so a reload can't revert a setting changed since startup. The *write* half keeps Electron's ~1x/second diffed poll. Close-to-tray also became synchronous — the flag is already mirrored into Rust state and seeded from `settings.json`, so no `executeJavaScript()` round-trip at close time.
  5. **One accepted gap**: `getPathForFile` always returns `null` there. No system webview can resolve a `File` back to an OS path, and Tauri's own path-carrying drag-drop event can only be enabled by suppressing the HTML drop events `philogg.html` needs to receive files at all — so dropping files keeps working and "Open File Location" is simply not offered for picker/drop-loaded files. File-association opens still reveal, through `revealLocalUrl`. Two smaller ones: macOS font names are approximated from font filenames (Linux `fc-list` and Windows PowerShell are exact), and the maximize button doesn't swap its glyph.
  6. **Release**: new `.github/workflows/tauri-release.yml`, structurally a copy of `desktop-release.yml` (manual dispatch, per-OS checkboxes turned into the matrix by the same `jq` step, `prepare` job creating tag `tauri-<sha>`, `fail-fast: false`, 5-attempt upload retry) rather than an extra dimension inside it — the Electron release path has to keep working. Linux builds on `ubuntu-22.04` for glibc reasons and installs the WebKitGTK dev packages; the upload step renames bundles to `PhiLogg-tauri-<sha>.<ext>` since Tauri has no `artifactName` template.
  **Verified end to end on Linux** (WebKitGTK under a headless X server): the page loads through the custom scheme, a `.log` passed on the command line is fetched and then re-fetched on every tail tick, `settings.json` is written, and a second launch with another `.log` exits immediately and routes its file into the running window. **Not yet run on Windows or macOS** — the window chrome is the part most likely to need adjustment there, which is what the wrapper is for; the macOS-only code paths aren't even compile-checked from this environment. New docs `docs/desktop-tauri.md` (written as a delta against `docs/desktop.md`) and `desktop-tauri/README.md`; `FEATURE_BACKLOG.md` #60 is the "does Tauri replace Electron" decision this defers. `tests/philogg.regression.test.js`: **Group 139** (a wrapper whose `getPathForFile` only ever returns `null` — exercising the *load* path Group 109 only ever stubbed) and **Group 140** (the `#toolbar` structure/50px-height contract both wrappers' injected chrome is keyed off, a tripwire for a rename that would silently break window chrome nothing else tests). 2685 passed, 0 failed.

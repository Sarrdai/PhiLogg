- **Tauri wrapper: two real-Windows bugfixes (window unmovable, empty window on last-file-close)** (this session, 2026-09-01, person-tested on Windows after setting the branch as a temporary default to trigger the tauri-release.yml build). Both root causes were places where a Tauri webview needs an explicit Rust round-trip that Electron gets for free.
  1. **The window couldn't be moved** — clicking empty toolbar space did nothing detectable at all. `data-tauri-drag-region` (which `inject.js` stamps onto `#toolbar`) is read by a script Tauri auto-injects into every window, which calls the core `start_dragging` command — and that command is deliberately *not* part of `core:window`'s default permission set (unlike `internal_toggle_maximize`, which is). `desktop-tauri/src-tauri/capabilities/default.json` now grants `core:window:allow-start-dragging` explicitly.
  2. **Closing the last open file** (`quitOnLastFileClose`) **left an empty, permanently-open dark window**, recoverable only via the tray's Quit. `philogg.html` calls the plain DOM `window.close()`, which Electron's `BrowserWindow` intercepts and turns into a real window close — a Tauri webview has no such interception, so the webview engine tore down the *page* (visibly "closing" the app) without ever notifying the Rust side, and `WindowEvent::CloseRequested` (and the close-to-tray decision behind it) never fired. `inject.js` now overrides `window.close` to `invoke("window_close")`, routing it through the same Rust-side path the injected title-bar close button already used.
  Verified: a temporary `visible(true)` + `xdotool` drag under Xvfb moved the window from (0,0) to (150,90); an `eval("window.close()")` smoke test confirmed the window hides (`is_visible() == false`) instead of staying open. `docs/desktop-tauri.md` and `desktop-tauri/README.md` → "Status" updated. `tests/philogg.regression.test.js` unaffected (Rust/injected-JS only) — 2685 passed, 0 failed.

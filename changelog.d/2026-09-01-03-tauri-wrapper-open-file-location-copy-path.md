- **Tauri wrapper: "Open File Location"/"Copy Path" now work for picked and dropped files, and a new "Copy Path" action everywhere** (this session, 2026-09-01, person-requested — the Tauri build could only reveal files opened by double-click, and the question was whether a permission grant would close that or whether it needed extra interaction). Neither: the wrapper's `reveal_path` command already worked and its own `#[tauri::command]`s need no ACL entry at all (`capabilities/default.json` is unchanged by this). What was missing was *knowing the path* — no system webview resolves a `File` back to an OS location, which is exactly what Electron's `webUtils.getPathForFile` does and why that function has always returned `null` there. The fix routes around the limitation instead of fighting it: **the wrapper opens the files itself**, so the path is known before `philogg.html` ever sees them — generalizing the route a `.log` file-association open already took.
  1. **Three routes, one mechanism.** "Open… → File(s)…" now defers to a new `philogg.pickFiles` bridge function that runs the OS dialog in Rust (`tauri-plugin-dialog`, driven from Rust — so still nothing added to the ACL); drag-and-drop is caught by Tauri's *native* handler (`WindowEvent::DragDrop` in `windows.rs`); file associations are unchanged. All three end at `state.register_local_file(path)` and hand the page both halves — the real path and the `philogg://local/<id>/…` URL the file is served under — through a new `window.philoggLoadLocalFiles({ files, folders })`. That builds ordinary load descriptors, so the queued placeholders, the multi-file merge prompt and tailing all behave exactly as they do for a dropped `File`; `node.localPath` and `node.sourceUrl` are both set, so the context menu offers everything it does under Electron. `loadFileDescriptors` gained support for a *lazy* descriptor (`name` + `openFile()`) so every placeholder is in the tree before the first byte is fetched, and now cleans up a placeholder whose read failed before `loadOneFileIntoTree` ever ran.
  2. **The drag-drop trade, reversed.** Tauri's native handler is the only one carrying OS paths, and enabling it suppresses the HTML drop events — the earlier version took the opposite side of that trade (`disable_drag_drop_handler()`) and accepted pathless drops. Two consequences, both handled: `philogg.html` never sees a `dragenter`, so the wrapper drives its drop overlay through a new named `window.philoggDropOverlay(show)` hook rather than reaching into `#dropOverlay`; and **a dropped folder can no longer start a folder watch** (that needs a live `FileSystemDirectoryHandle` to list and rescan, which a path can't produce) — folders are reported in the same call and the page points at "Open… → Folder…" instead. Accepted with the person up front. Folder watch stays this wrapper's one pathless route — `FEATURE_BACKLOG.md` #61.
  3. **New "Copy Path" context-menu action**, in *both* wrappers, on exactly the same gate as "Open File Location": a known `node.localPath` goes straight to the clipboard; a `philogg://local/…` file — which the page knows only by that URL — has its path fetched back through a new `pathForLocalUrl(url)` bridge function (`path_for_local_url` in Tauri, `philogg:path-for-local-url` in Electron; the same id → path lookup `revealLocalUrl` does, handing the answer back instead of acting on it). Person-requested as the fallback that's useful even when revealing isn't — pasting a path into a terminal or a ticket.
  4. **Bugfix found on the way: every URL-opened file was silently missing from the session cache.** `persistFileNode` stashed `node.tail.handle` in the IndexedDB record; for a `?url=` deep-link or a file-association open that handle is a `urlTailHandle`, a plain object holding a closure, which structured clone rejects with a `DataCloneError` — and `cacheStoreOp` swallows the synchronous throw, so the *entire* record was quietly never written and the file vanished from "restore last session". This predates the Tauri wrapper and affected Electron too. URL-backed handles are no longer persisted (they're marked with a symbol-ish key and skipped) and are rebuilt from the already-persisted `sourceUrl` on restore — which also means those files now resume *tailing* after a reload, with no permission round-trip.
  **Verified**: the Rust side compiles clean; the page side is covered by new **Groups 141-144** in `tests/philogg.regression.test.js` (the pick/load route incl. tailing, the multi-file batch, the failed-read cleanup; both "Copy Path" variants and its absence in a plain build; the overlay hook and the dropped-folder report; the cache round-trip, confirmed to fail without the fix). Group 139's framing was re-pointed at the case that *is* still pathless there (folder watch) rather than left describing a route that no longer exists. **Not yet run on Windows** — two things to check there: that the internal filter-node drag-and-drop in the tree still reparents now that Tauri's native drop handler is on, and the native dialog/drop themselves.

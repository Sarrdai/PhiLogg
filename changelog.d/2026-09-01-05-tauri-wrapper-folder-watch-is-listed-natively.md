- **Tauri wrapper: folder watch is listed natively — Desktop works, and so do macOS/Linux** (this session, 2026-09-01, person-reported: watching a folder like Desktop failed in the Tauri build the same way it does in Chrome, and the question was whether Tauri can simply allow it). **It can't, and no embedder can.** `philogg.html`'s folder watch went through `window.showDirectoryPicker()`, which is a *webview engine* API: Chromium refuses a directory handle for anything on its hardcoded sensitive-directory list (`ChromeFileSystemAccessPermissionContext` — Desktop and Downloads among them, hence the "this folder contains system files" error), the check runs inside the engine after the call, and there is no Tauri setting and no WebView2 browser flag that turns it off. The fix is to stop asking the webview: this wrapper now lists watched folders **in Rust**, which has no blocklist. That is `FEATURE_BACKLOG.md` #61, and it closes all three of its gaps at once — the blocklist, the fact that folder watch previously existed *only on Windows* (WKWebView and WebKitGTK don't implement the API at all), and the missing path on files opened from a watched folder.
  1. **Two new Rust commands, one new stand-in.** `pick_folder` runs the OS folder dialog (same Rust-driven `tauri-plugin-dialog` route as `pick_files`, so still no ACL entry — `capabilities/default.json` is unchanged), `list_folder(path, extensions)` does a non-recursive `read_dir` filtered by the extensions the *page* considers loadable and registers each match like any other file the wrapper opens. On the page side, `nativeDirHandle()` is a duck-typed stand-in for a `FileSystemDirectoryHandle` — `name`, `values()`, `queryPermission()`, `requestPermission()`, the four members the folder-watch code actually uses — so `scanFolderHandle`, `mergeScannedFiles`, `rescanFolder`, `folderScanTick` and `tryReconnectFolder` are untouched. Each listed entry *is* a `urlTailHandle` (now carrying the file's path alongside its URL), so tailing comes along for free, exactly as it does for a picked or dropped file.
  2. **Folder-watched files finally know where they are.** They were the last route in `desktop-tauri/` with no `node.localPath`, i.e. the only files there without "Open File Location"/"Copy Path". A natively listed file arrives with both halves, applied by the new `applyFolderFileLocation()` on load *and* on every rescan — the ids behind `philogg://local/<id>/…` are per-process, so a session restored from cache holds the previous run's dead URLs until the first scan re-registers them.
  3. **A dropped folder starts a watch again.** The previous session had accepted losing that (the native drag-drop handler carries paths but no directory handle); a path is now exactly what a watch wants, so the "use Open… → Folder…" notice is gone for this wrapper and stays only for one that can't list folders.
  4. **Persistence.** A stand-in holds a closure, which structured clone rejects outright — the same trap the `urlTailHandle` cache bug fell into. `persistFolder` stores the folder's **path** instead of the handle and `restoreWatchedFolders` rebuilds the stand-in from it; a rebuilt one answers `queryPermission()` with `"granted"`, so a restored native folder resumes silently and never shows the "Reconnect" button (a path, unlike a handle, needs no permission re-grant). A real `FileSystemDirectoryHandle` still travels as itself, unchanged.
  5. **`register_local_file` now dedupes by path.** It minted a fresh id per call; with a rescan every 3 s per watched file that would have grown the map without bound and handed the page a new URL for a file it was already tailing.

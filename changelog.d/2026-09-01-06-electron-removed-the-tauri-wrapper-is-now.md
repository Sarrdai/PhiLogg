- **Electron removed; the Tauri wrapper is now simply the desktop build, and release builds ship comment-free HTML** (this session, 2026-09-01, person-requested — retire the Electron build completely, "including comments, documentation, workflows"; make both build paths strip `philogg.html`'s comments for release only; and, in a follow-up the same session, drop the `-tauri` suffix everywhere now that nothing needs distinguishing). This settles `FEATURE_BACKLOG.md` #60 (the keep-both-or-retire-one decision) by retiring Electron; #62 (an Electron-only folder-watch escape hatch) and #34 (an Electron-only scrollbar artifact) are retired with it, #35's wording is no longer Electron-specific, and #63 (the naming question) was raised and answered inside this same session.
  1. **Deleted**: the Electron `desktop/` (`main.js`, `preload.js`, `package.json`, `electron-builder.yml`, its README), its release workflow, and its `docs/` file. Nothing in the Tauri wrapper depended on any of it at build time.
  2. **The wrapper's `docs/` file is now self-contained.** It was written as a *delta* against the Electron one, so deleting that would have taken the shared mechanism with it. Rewritten as the single desktop-wrapper reference: the `philogg://` scheme and the `fetch` shim, the injected script and the `window.philogg` bridge, the native file/folder routes, frameless window and drag region, "Open File Location"/"Copy Path", the system font list, settings mirroring, tray/splash/close-to-tray/single-instance, release and capabilities. `desktop/README.md` lost its "Differences from the Electron wrapper" section in favour of "Known limitations".
  3. **Comment sweep**, since the ask covered comments as well as files: every Electron reference in `philogg.html` (7 blocks), `tests/philogg.regression.test.js` (13, mostly GROUP headers and TEST PROVENANCE entries), the wrapper's Rust/JS sources, `PROJECT.md`, `README.md`, `CLAUDE.md`, `FEATURE_BACKLOG.md`, `docs/persistence-and-sync.md` and `docs/ui-and-views.md` was rewritten to describe the mechanism generically or in Tauri's terms. Where a comment explained a behaviour *by contrast with* Electron (`getPathForFile` always returning null, the `window.close()` routing, the drag-region attribute not being inherited), the reasoning was kept and the comparison dropped — the facts are about what a system webview does, not about what Electron did. `philogg.html`'s own `getPathForFile` probe is deliberately **kept**: it is a generic wrapper hook, it costs four lines, and removing it would be a behaviour change to the page rather than a build removal. Older changelog entries are left exactly as they are — this file is the dated record of what happened, not a description of the current state.
  4. **Release-only comment stripping** (`scripts/strip-comments.js`, new). The tracked `philogg.html` keeps every comment; the copies that leave the repo carry none — about **42% of the file**, 1.08 MB → 632 KB. `release.yml` runs it on the stamped asset before publishing, `tauri-release.yml` on the checked-out copy before the bundler packages it as a resource, so both artifacts carry identical content; neither is ever committed back, and a local `npm run build` in `desktop-tauri/` does neither. It is a comment stripper, **not** a minifier — whitespace, names and line structure survive, so a stack trace from a release build still lands on a recognizable line; a comment that occupied a whole line takes the line with it, which is where nearly all of the saving comes from.
  5. **Why it is a hand-written scanner** rather than a regex: `philogg.html` is full of strings containing `//` (the `philogg://` scheme, every URL) and of regex literals containing quotes and slashes, so anything less corrupts the file silently. It tracks strings, template literals including nested `${}` interpolation, and regex literals (with character-class awareness, so `/[/*]/` doesn't end early); the one genuinely ambiguous case, `/` after `}` or a keyword, uses the standard previous-token heuristic. Dependency-free, so a release job needs no `npm install` to run it, and it fails the build outright if its own output no longer parses.
  **Verified**: `tests/philogg.regression.test.js` gained **Group 146** (comment removal and whole-line collapsing; then every "looks like a comment but isn't" case; then the real `philogg.html` end to end — idempotent, a subsequence of the original, version line intact, still parseable). The load-bearing check is the suite itself run twice: **2785 passed, 0 failed** against the tracked file, and **2785 passed, 0 failed** against the stripped copy (`PHILOGG_HTML=…`) — same count, so nothing the suite exercises behaves differently without comments. The Rust side of `desktop-tauri/` was comment-only in this session and is otherwise untouched. See point 6 for the naming follow-up.
  6. **`-tauri` dropped everywhere** (person-requested follow-up, same session: the app is unpublished, so there are no installs whose `settings.json` a moved config directory could orphan — which was the only thing holding this back). `desktop-tauri/` → `desktop/`, `docs/desktop-tauri.md` → `docs/desktop.md`, `tauri-release.yml` → `desktop-release.yml`; product name `PhiLogg Tauri` → **`PhiLogg`**, bundle identifier `com.kleinphilipp.philogg-tauri` → **`com.kleinphilipp.philogg`**, config directory `PhiLogg-Tauri/` → **`PhiLogg/`** (`~/.config/PhiLogg`, `~/Library/Application Support/PhiLogg`, `%APPDATA%\PhiLogg`), crate/bin/npm package `philogg-tauri` → `philogg-desktop`, release tag `tauri-<sha>` → `desktop-<sha>`, installers `PhiLogg-tauri-<sha>.<ext>` → `PhiLogg-<sha>.<ext>`. Names that describe the *framework* rather than the product are deliberately left alone: `src-tauri/`, `tauri.conf.json`, `data-tauri-drag-region`, the `#tauri-wc` window-control block `inject.js` injects, and the `tauri-plugin-*` dependencies. **Verified**: `cargo check` clean under the new crate name, `Cargo.lock` needed only its own package-name line changed (`cargo metadata` left it otherwise untouched), and the suite still reports 2785 passed, 0 failed against both the tracked and the stripped file.

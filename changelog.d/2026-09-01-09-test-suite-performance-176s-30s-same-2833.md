- **Test suite performance: 176s → ~30s, same 2833 assertions** (this session, 2026-09-01, person-requested performance review: *"Das Durchlaufen der Tests benötigt aktuell einen Großteil der Bearbeitungszeit"*). Profiled first: the suite builds ~290 jsdom windows and **78% of its runtime was window construction**, not assertions — the section-duration distribution was flat (median 0.52s, p90 1.22s), so there was no slow group to optimize. Splitting one window's ~470ms further: ~75ms HTML parse, ~48ms CSS parse, and **~350ms compiling the same 871 KB inline `<script>`** — V8 re-compiling identical source 290 times.
  1. **The page script is compiled once** (`vm.Script`) and run into each new window's VM context via `dom.getInternalVMContext()`, instead of being left inline for jsdom to re-compile per window. Per-window construction dropped ~470ms → ~135ms; the suite went **176s → 78s** with a byte-identical `2833 passed, 0 failed`. Safe here because `philogg.html` has exactly one `<script>`, it is the last element in `<body>`, and the app hooks neither `DOMContentLoaded`/`load` nor `readyState`/`document.currentScript` — so running it after the parse is equivalent to running it inline. `runScripts` deliberately stays `"dangerously"`: the ~30 test sites that inject their own bridge `<script>` elements (including `withApp`'s `window.__t`) depend on it.
  2. **The reload groups no longer poll a proxy condition** — a latent flake the speed-up exposed rather than caused. They spun `for (let i = 0; i < 40 && state.rootIds.length === 0; i++) await sleep(50)` and then asserted on `localPath`, `columnVisible`, the filter tree, bookmarks — but `restoreSessionFromCache`'s **first** pass fills `rootIds` with grayed queued placeholders, long before any of that lands. They were green only for as long as window construction stayed slow; at a faster boot two trial runs went red in two *different* places. `philogg.html` now **names its boot promise** (`const bootRestore = restoreSessionFromCache().then(... restoreWatchedFolders())`) — previously a floating promise — which the bridge exposes as `T.bootRestore`, giving all 13 reload groups one exact "restore has settled" barrier to await instead of a guess. GROUP 127 deliberately keeps polling: it asserts on the *intermediate* restore state, so it uses the new `waitFor(pred)` helper on the structural moment it actually needs. The 10 duplicated local `sleep` helpers are hoisted to one module-level definition.
  3. **`npm test` now shards across cores** via a new `tests/run.js` (~30s on 4 cores). Every `GROUP` banner carries a `group(N);` marker; `withApp` returns without building a window when that group belongs to another shard, and `run.js` sums the shards back into the single `N passed, M failed` line — so a group that silently stopped running shows up as a lower count. The shard unit is the **group**, never the individual `withApp`: multi-window reload groups hand one `IDBFactory` and closure state from window to window, and sub-lettered banners (30a-e, 55a-d, 73b/c) share their number so they stay together. `SHARDS=1 npm test` (or `npm run test:single`) runs it in one process; **`GROUP=58 npm test` runs a single group in ~2s**, which is the loop to use while iterating on a feature.
  Verified: `2833 passed, 0 failed` at every step, the shard partition is disjoint and complete (140 groups over 35/36/35/34), forced failures still aggregate across shards with exit code 1, and three consecutive sharded runs were green.
  **Rejected after measuring**: pre-stripping the HTML/CSS comments out of the shell with `scripts/strip-comments.js`. It does cut construction to ~113ms, but only ~8s end-to-end, and the suite went red in both trial runs. Not a stripper bug — the full `stripDocument(html)` that `release.yml` ships passes 2833/0 — just not worth the fidelity loss.
  `CLAUDE.md`'s "when to run the suite" rule was tightened in the same pass: it demanded a full run for **anything** under `desktop/`, but the suite never builds Tauri and never reads a file there (the wrapper groups drive `philogg.html` against faked `window.philogg`/`nativeDirHandle` bridges), so a change confined to `desktop/src-tauri/**` gets zero signal from it and needs `cd desktop && npm run build` instead.

- **Filter popup: "Match whole word", and every popup toggle now uses the Settings switch** (this session, 2026-09-01, person-requested: *"Im Filter Edit Fenster ergänze die Option 'Match whole word' … Bei der Gelegenheit: Vereinheitliche die Darstellung der Checkboxes. Nutze den Style der Toogles aus den Settings auch hier."*).
  1. **`node.wholeWord: boolean`** on an ordinary `"text"` filter node, **default off** as specified — no new `filterType`, the same additive shape `caseSensitive`/`columns`/`isRegex` already use, and it combines freely with all three. `"Test"` now matches `"Test is active"` and `"unit-Test done"` (a hyphen is a boundary) but not `"Testing activated"`/`"retest pending"`.
  2. **Matching is a boundary-checked `indexOf` scan** (`includesWholeWord`/`isWordChar`), not a `\b`-wrapped `RegExp`: `\b`'s word class is ASCII-only, so it would have called `"Gr"` a whole word inside `"Größe"` — wrong for German log text, which is most of what this option is for. `WORD_CHAR_RE` is `/[\p{L}\p{N}_]/u` instead, and the scan keeps the hot filter path allocation-free. `textFilterMatches` takes it as a trailing argument and honours it in its literal branch, column-restricted or whole-line.
  3. **Literal matches only, and visibly so.** A real regex (`\b`, lookarounds) and the wildcard-token language (`[value:word]`, `[*]`) express boundaries themselves, so the flag has no definition there. Rather than let a checked box silently do nothing, `updateWholeWordAvailability()` greys the toggle out (with a tooltip saying why) the moment regex mode is on or the input carries wildcard tokens, and `commitFilter` refuses to store the flag on such a node at all — the same kind of pure capability gate `#filterExtractBtn.disabled` already was, driven off the same `"input"`/regex-`change` listeners via a shared `updateFilterAvailability()`. Match highlighting follows the same rule (`textFilterMatchSpec` carries `wholeWord`, `findMatchRanges` skips a glued occurrence), so a marked span is always one the filter accepted.
  4. **Threaded through every persistence carrier** per CLAUDE.md's "Known gotchas": `cloneSubtree`, `snapshotSubtree`/`restoreSubtree`, the field-edit-undo `captureNodeFields`/`applyNodeFields`, `serializeFilterBranch`/`importFilterJson`, `serializeFilterTreeForCache`/`materializeCachedFilters`, plus `bakeNodeCondition`/`getEntriesFromBaked`/`materializeBaked` so an AND/OR/LINK side keeps the flag it was baked with.
  5. **Checkbox presentation unified**: all four booleans in `#filterPopup` (regex mode, `Aa`, "Match whole word", `NOT`) now render as the same on/off switch the Settings rows use — `.settings-switch` in a new compact `.settings-switch-sm` size, inside a shared `.filter-toggle` row that replaces the three near-identical `.filter-regex-toggle`/`.filter-case-toggle`/`.filter-invert-toggle` rules; `.filter-toggle-danger` keeps `NOT`'s red accent. The `<input type="checkbox">` underneath is untouched, only its appearance is replaced, so every `.checked`/`change` path still works as before. Switch and caption are two separate `<label>`s (nested labels are invalid HTML) with the caption carrying `for=`. The other dialogs' checkboxes (link options, plot controls, column menu, session export) are deliberately left as they were — the ask was scoped to the filter edit window.

- **Desktop (Windows): Alt+Enter no longer pops the native system menu** (this session, 2026-09-02, person-reported: extracting a filter with Alt+Enter and then pressing Enter again opened a blank window menu top-left). Cause was WebView2's own handling of Alt as a browser "accelerator key" — the same mechanism Chrome/Edge use to focus a menu bar — firing even though `philogg.html`'s Alt+Enter handler already calls `preventDefault()` on the keydown; the frameless window (`decorations(false)`) has no menu bar of its own, so Windows falls back to the native system menu instead. `desktop/src-tauri/src/windows.rs`'s `create_main` now calls a new `disable_alt_accelerator_keys` (Windows-only) right after building the main window, reaching into the WebView2 controller via `webview2-com`/`windows` (added as `cfg(windows)`-only dependencies in `desktop/src-tauri/Cargo.toml`) to set `ICoreWebView2Settings3::SetAreBrowserAcceleratorKeysEnabled(false)`. No test suite coverage — this is Rust/Tauri-side only, nothing the jsdom regression suite loads; verified by reading the WebView2 API, not by an actual Windows build in this session (no Windows toolchain available here).

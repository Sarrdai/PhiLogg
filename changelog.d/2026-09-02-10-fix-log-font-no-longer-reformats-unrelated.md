- **Fix: Log font no longer reformats unrelated UI chrome, and setting order no longer matters** (this session, 2026-09-02, person-reported follow-up to the entry below: *"Die Änderung des Fonts scheint sich nicht sofort auf alle Angezeigten Elemente zu wirken... Es wirkt zum Beispiel so, als wären die Level Filter Buttons formatiert wie die Log Einträge."*). Root cause: the new Log font picker (below) drove `--font-mono` directly, but a good number of unrelated UI-chrome elements — `.level-btn` (the level-quick-filter pills), badges, dialog inputs, plot tick labels, session-file rows, etc. — *also* style themselves off `--font-mono` purely for its own monospace look, unrelated to actual log content. So picking a Log font visibly reformatted those UI elements too, and since both the UI font's "Monospace" option and the Log font picker ultimately wrote into the same custom property, whichever was set last could appear to "win" — reading as order-dependent. Fixed by introducing a dedicated `--font-log` custom property, used *only* by the exact set of selectors `--log-text-scale` already scopes to (`.col-time`, `.col-delta`, the level badge, `.col-thread`, `.col-loc`, `.col-method`, `.col-msg`, `#entryDetail`'s message body, `#extractTable`, `.pair-row-time`, `.pair-row-msg` — i.e. table rows, extraction table, entry detail message, link/pair rows, matching `PROJECT.md`'s own definition of "log/text content"). `--font-mono` reverted to fixed/non-configurable, still covering the UI chrome's own monospace bits exactly as before this session. `applyLogFont()` now sets `--font-log` instead of `--font-mono`; `LOG_FONT_OPTIONS`' default stack is unchanged, so existing Log font selections keep behaving the same. `tests/philogg.regression.test.js`: **Group 153** updated throughout to assert on `--font-log`; two new sections — 153c confirms `--font-mono` (and thus `.level-btn`) is untouched by the Log font setting and that a log-row cell/level button resolve to genuinely different font stacks once Log font diverges from default, 153d confirms UI-font-then-Log-font and Log-font-then-UI-font land on the identical end state. **3007 passed, 0 failed** (3002 + 5).

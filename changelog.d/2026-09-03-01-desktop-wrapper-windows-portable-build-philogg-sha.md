- **Desktop wrapper: Windows portable build — `PhiLogg-<sha>_portable.zip`, run straight off any drive with no install and nothing written to the host machine** (this session, 2026-09-03, person-requested). `settings::portable_dir()` detects a `philogg-portable` marker file next to the running exe; when present, `config_dir()` (`settings.json`) and `create_main`'s new `WebviewWindowBuilder::data_directory(...)` call (the webview's own storage, IndexedDB session cache included) both point at a `data\` folder beside the exe instead of the OS's per-user directories, and `html_path()` gains an exe-adjacent `philogg.html` fallback since the portable build has no installer/resource dir to read it from. The tray's "Open Config Folder"/"Clear Cache" needed no change — both already go through the same `config_dir()`/webview APIs. `.github/workflows/desktop-release.yml` gets a fourth checkbox, `build_windows_portable` (default off), which — deduped against `build_windows` for the shared `windows-latest` runner — zips the raw unbundled `philogg-desktop.exe` from the same build together with the stamped `philogg.html` and an empty `philogg-portable` marker, uploaded alongside the installer. Windows-only: WebView2 ships with Windows itself, so there's no equivalent "no install" story on macOS/Linux to build a portable variant for. See `desktop/README.md` → "Portable build (Windows)" and `docs/desktop.md` for both the persistent-data and release-workflow detail.

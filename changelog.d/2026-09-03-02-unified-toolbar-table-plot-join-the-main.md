- **Unified toolbar: Table/Plot join the main Context/Filtered/Stacked tab group instead of their own separate sub-toggle** (this session, 2026-09-03, `docs/ui-implementation-plan.md`). `#fhTabs` now renders `Context | Filtered | Table | Plot` ("Separate", default) or `Stacked | Table | Plot` ("Stacked") depending on a new Settings → Behavior → "Context/Filtered display" option — the only way `fhLayout` changes now; the old "Stacked" tab button that used to set it directly is gone. Table/Plot stay visible but `disabled` (not removed) when the active node has no extractable wildcards (`nodeHasExtractableWildcards`), so the rest of the tab group never shifts sideways. The `isExtract` special path in `renderMainView()` is gone entirely: an extraction node is now an ordinary node for Context/Filtered/Stacked purposes too (it already had real matched entries via `getEntries()`), and just additionally unlocks Table/Plot; activating one still auto-reveals its Table tab, same as before. `#extractViewTabs` (the old Table/Plot sub-toggle inside the extraction toolbar) is removed outright. One deliberate scope-cut versus the plan's original "physical slot row" idea (Schritt 4): `#contextToolbar`/`#extractToolbar`/`#plotToolbar`/the six log-view toggles stay in their pre-existing DOM locations rather than being reparented into a new shared container — reparenting them broke roughly ten existing regression tests asserting that exact DOM structure, more than could be responsibly migrated in the session; only each one's show/hide *condition* changed, from `isExtract`/always-on to `fhActiveTab`-driven.

A node that has **never been the active node before** (no entry yet in the new in-memory `nodeLastView` Map, keyed by node id) always lands on Filtered now, regardless of wildcards or the setting below. A node visited before goes by the new **"When switching to a filter"** row (`#settingsFilterActivationView`, backed by `filterActivationView`/`FILTER_ACTIVATION_VIEW_KEY` in `localStorage`, same wiring shape as the neighboring "Context/Filtered display" row): `"rememberLast"` (default) restores whichever tab — Context/Filtered/Table/Plot, or the merged Stacked pane — was last shown for *that specific node*; `"alwaysFiltered"` always lands on Filtered again. `nodeLastView` is recorded at the end of every `applyFhView()` call (the one place every tab switch funnels through, not just `applyActivationView` itself), so it stays live from ordinary tab clicks too; it's intentionally in-memory only, a per-session convenience like scroll position rather than part of the filter definition. Two sane fallbacks to Filtered instead of a dead/invalid tab: a node remembered on Table/Plot whose pattern was edited since to drop its wildcards (`nodeHasExtractableWildcards` now false), and a node remembered as `"stacked"` after the person has since switched the global "Context/Filtered display" setting back to "Separate". One behavioral widening worth flagging: this also changes *plain* (non-extraction) filter nodes — under `rememberLast`, reactivating a filter last left on the Context tab now restores Context instead of always forcing Filtered, superseding that part of Group 61's original "switching filters auto-reveals Filtered" coverage.

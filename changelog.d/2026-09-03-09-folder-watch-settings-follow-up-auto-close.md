- **Folder watch settings follow-up: "Auto-close — keep only N open" now slides its window instead of stalling, and a relative-path name now survives opening the file** (this session, 2026-09-03, person-reported, follow-up to the settings dialog below). Two bugs: (1) `applyFolderAutoRules`'s auto-close rule only ever closed excess open files — it never opened the newer file that pushed the count over N, so with 2 already open and a 3rd, newer match appearing, the new one silently stayed unopened instead of the intended "oldest closes, newest opens, the N newest stay open." Rewritten as a genuine sliding window: for a pattern with `autoCloseKeep` set, `recs.slice(-N)` (the N newest) is computed first, whichever of those aren't open yet are opened (awaited), THEN whatever is open but fell out of that window gets closed — so a new arrival correctly evicts the previous oldest. "Auto-open newest file" (no keep-N configured) is unchanged, and is now explicitly skipped for a pattern that also has `autoCloseKeep` set, since that pattern's own window already covers it. (2) `nodeDisplayName()` (the one function every name display — tree row, breadcrumb, tab — already reads through) didn't know about a folder-watch file's `relPath`, so a file opened with "Show relative path" on reverted to its bare filename the instant it was loaded, even though the still-grayed listing kept showing the full path. `nodeDisplayName` now looks up a `folderId`-tagged file node's owning folder and, when `includeSubfolders`+`showRelativePath` are both on, returns its listing record's `relPath` instead of `node.name` — display-only, exactly like the pre-existing `node.label` override for filter nodes, so the underlying `node.name` (identity, matching in `folder.files`) is untouched. `tests/philogg.regression.test.js`: **Group 164** (extended in place) — the sliding-window scenario (2 open, keep-2, a newer 3rd file arrives → opens, the previous oldest closes, the still-in-window one is left untouched) plus a "Show newest M" follow-on with two open files; `nodeDisplayName()` and the actual tree row both keep showing the relative path after double-clicking to open the file. **3226 passed, 0 failed** (3224 + 2 net, after rewriting 3 pre-existing assertions in place for the new fixture).

- **Link filter view: row click, Up/Down and Alt+Enter now act on the whole pair/tuple, not a single line** (this session, 2026-09-04, person-reported). Previously a click on a `.pair-row` did nothing at all (only the brace's own click selected the pair), Up/Down was a deliberate no-op in the Link view, and keyboard Alt+Enter wildcard-filtered whichever single real entry `state.selectedId` happened to still hold from an earlier row double-click — not the pair — because it read `entryIndex[state.selectedId]` unconditionally and a pair's synthetic id is never registered there. `buildPairBlock` now attaches the pair-selection click handler (toggle-select by index, same as before) to the whole `.pair-block` instead of only the `.pair-brace`, so clicking any row selects that row's pair. A new `moveLinkSelection(delta)` drives Up/Down through `linkSelectedPairIndex`, scrolling the target block into view via `linkBlockOffsets` and re-rendering the virtualized window; the arrow-key handler's former Link-view no-op branch now calls it instead. The global Alt+Enter handler checks for an active Link-view block selection first and, when present, calls `openFilterForEntryColumn` with the *pair* object (`linkPairsData[linkSelectedPairIndex].pair`) — byte-identical to what right-click brace → "Filter for this message" already produced, since that mechanism only ever worked because it was handed the pair object, not because of any bracket-specific code path — falling back to the previous single-entry path otherwise.

- **Entry detail: "format + syntax highlight" toggle for embedded XML/JSON** (this session, 2026-09-04, person-requested). `#detailFormatToggle`, a single `.panel-toggle-btn` next to `#detailToggle` in `#detailPanelHeader`, turns on/off pretty-printing + syntax-highlighting for well-formed XML/JSON fragments embedded anywhere inside the entry detail message's free text (e.g. `Sending Control <ctrl><cmd>reset</cmd></ctrl> successful`, or `Response: {"status":"ok"} done`), leaving the surrounding text untouched — persisted as one global on/off (`localStorage["philogg-detail-format-highlight"]`), default off. Detection is two-pass, never trusting a regex alone: `findEmbeddedFragments` scans for candidate spans (a balanced `<tag>...</tag>`/`<tag/>` run, or a bracket-matched `{...}`/`[...]` span, string-aware) and validates each one — `DOMParser`/`"application/xml"` checked for a `parsererror` node, or `JSON.parse` — before ever treating it as a hit, so a stray `<`/`{` used as everyday punctuation is left as plain text. `formatXmlFragmentHtml`/`formatJsonFragmentHtml` re-walk the already-validated parsed structure into indented, `<span class="syn-*">`-wrapped HTML, `escapeHtml`-ing every real piece of text the same way the rest of the app does — only the wrapper `<span>` tags are real markup, so an unmatched/malformed fragment (however script-shaped) never becomes live DOM. New CSS custom properties `--syntax-tag`/`--syntax-attr-name`/`--syntax-attr-value`/`--syntax-string`/`--syntax-number`/`--syntax-key`/`--syntax-boolean-null`/`--syntax-punct` (`SYNTAX_COLOR_KEYS`, parallel to `THEME_COLOR_KEYS`) get fixed hardcoded defaults in `:root`/`:root[data-theme="light"]` only — every other theme (the four Catppuccin flavors, any custom/imported theme) is free to skip them entirely and inherit those defaults via the normal cascade, or to override them via an optional `syntaxHighlightColors` block in its JSON, applied the same optional way `applyTheme()` already applies `THEME_COLOR_KEYS`. `buildThemeTemplateJson()`'s downloaded template now seeds that block from the active theme's own computed colors plus a sibling `_syntaxHighlightColors_comment` hint string (JSON has no real comments); `importThemeJson()` treats the whole block, and each of its keys, as optional — never rejects a file for lacking it, unlike `THEME_COLOR_KEYS` — and drops the hint field on import rather than storing it. `tests/philogg.regression.test.js`: **Group 169** (new) — toggle default/persistence/gating; XML detection+highlight (tags, attribute names/values, nesting, self-closing); JSON detection+highlight (keys, string/number/boolean/null); conservative-detection cases that must stay plain text (`a < b`, `if (x < y) { ... }`, an unclosed tag, a malformed JSON span); XSS safety (an unmatched tag never becomes real DOM, a validated fragment's special characters are re-escaped not injected raw); the theme template/import round trip for the optional `syntaxHighlightColors` block, with and without it present. **3330 passed, 0 failed** (3295 + 35).

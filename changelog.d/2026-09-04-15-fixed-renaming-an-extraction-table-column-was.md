- **Fixed: renaming an extraction table column was impossible while its file was being tailed** (this session, 2026-09-04, person-reported: F2/right-click "Rename column…" jumped straight back out of edit mode). Root cause: `onTailChange` (fired by `tailTick` on every new chunk of a live-tailed file) calls `render()` unconditionally, which reaches `renderExtractTable` and rebuilds `extractHead.innerHTML` from scratch — including while a rename `<input>` was focused. Detaching a focused element fires `blur` on it synchronously, and the input's own blur handler commits/cancels the rename, so any tail tick landing mid-edit ended it before the user had typed anything; a fast-growing file made this happen on essentially every keystroke. `renderExtractTable` now checks upfront whether the currently-focused element is the live rename input for `renamingColIndex` and, if so, skips rebuilding the header entirely (row data below still refreshes normally) — the input keeps its focus, caret and in-progress value until the user actually commits (Enter/blur) or cancels (Escape). `tests/philogg.regression.test.js`: **Group 157 extended** — 157c (new) simulates a `renderExtractTable` call landing mid-rename (standing in for a tail tick's `render()`) and asserts the same input survives with its in-progress value and focus intact, then still commits normally afterward. **3387 passed, 0 failed** (3384 + 3).

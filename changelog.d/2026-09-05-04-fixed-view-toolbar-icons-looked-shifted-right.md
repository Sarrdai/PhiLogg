- **Fixed: View Toolbar icons looked shifted right at rest** (this session, 2026-09-05, person-reported follow-up to the rectangle-expand mechanic). Root cause: `.toolbar-icon-btn:has(.tb-hit)` overrode `justify-content` to `flex-start` (needed, it seemed, for the label to sit to the right of the icon once expanded) — but this stylesheet's global `*{box-sizing:border-box}` means a 28px button's actual content box is only 26px (28px minus its 1px border on each side), so the 28px `.tb-hit` inside it always overflows by 2px somewhere. With the base rule's `justify-content:center` (what `.row-action-btn` already relies on, unchanged), that 2px overflow is split evenly and clipped symmetrically on both sides — invisible. `flex-start` instead clipped only the right edge, visibly shifting the icon off-center. Fix: dropped the `justify-content` override entirely — `width:auto` on expand leaves no slack for `justify-content` to distribute either way, so centering was never actually needed for the expand mechanic to work; removing it restores symmetric clipping at rest, same as `.row-action-btn`. Pure CSS fix, no structural/DOM changes — no new tests needed.

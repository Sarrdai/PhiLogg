- **Picture-in-picture (PiP), replacing the abandoned popout-window approach** (this session, 2026-09-07, person-requested). The `claude/popout-window-feature-b87cwa` branch built "popout" as a second `WebviewWindow` mirroring the active view; its whole history is sync bugs (missed pushes, `JSON.stringify` dropping negative indices, blank containers, tailing never engaging) plus a window-creation deadlock on Windows (tauri-apps/wry#583), all of which trace back to *making a second copy of the app*. This replaces it with the opposite design: **no second window, no pushed state, no sync, no jump-back IPC.** The *same* `philogg.html` instance — same `state`, same DOM, same render pipeline, same real nodes — becomes the PiP, so the sync bugs are impossible by construction. **Trigger is a dedicated button, not a setting**: a diagonal `<->` window-control button (left of minimize, in the injected `#tauri-wc` controls) invokes `pip_enter`, which shrinks the one window in place to `420×320`, sets it always-on-top, and CSS-hides all chrome (`html.pip-mode`) except the active content view. The mini window gets its own slim injected strip (`#tauri-pip`, only visible in `html.pip-mode`, doubling as the drag handle): the **ViewMode switcher (`#fhTabs`) sits at its far left** (`html.pip-mode` collapses `#viewBar` and `position:fixed`-s the tabs into the strip, so the switcher stays usable), a diagonal `<->` on the right returns to the full window (`pip_exit`), and an X that does **not** close the app but ends PiP and minimizes the full window back to the taskbar (`pip_minimize`, restore-then-minimize ordering). Double-clicking an empty spot of the strip also expands back to the full window's **windowed** state (never maximized) — `interceptDragDoubleClick` grabs the drag region's second `mousedown` (`detail === 2`) ahead of Tauri's own drag script (which otherwise fires `internal_toggle_maximize`). F11, the toolbar's double-click, and the injected rectangle button are all **equivalent to the same native maximize/restore** (`window_toggle_maximize` / `internal_toggle_maximize`): a borderless *fullscreen* was tried first, but its "restore on drag" had to be hand-rolled and never felt native, so fullscreen was dropped in favour of maximize — which restores under the cursor the same way whichever trigger entered it. An interaction that jumps to another view also exits PiP first, via the page's `jumpAfterPip` helper (threaded through the six jump entry points: link-view dblclick, Context-row dblclick, extraction-row dblclick, 2D/3D plot-mark click, and the Enter reveal), awaiting `window.philogg.exitPip` so the reveal's scroll/anchor math runs against the restored viewport. `jumpToEntry` has no UI call site on main, so there was nothing to thread. Both modes remember their own position + size (`state.rs` keeps `pip_active`, plus `full_prev`/`full_was_maximized` for the full window and `pip_prev` for the mini window): `enter_pip` leaves maximize *before* capturing the full window's windowed bounds — which is what guarantees going maximized → windowed lands on the full windowed size, never the mini size — and `exit_pip` re-applies that windowed position + size first (resetting the OS's restore size so a later unmaximize/drag-out-of-maximize never lands on the mini size), then re-maximizes if that was the state at entry, while remembering the mini window's own geometry for the next enter. `commands.rs` gains `pip_enter`/`pip_exit`/`pip_minimize`; `window_minimize` is back to a plain minimize; `inject.js` adds the `<->` button and the `#tauri-pip` strip. See `docs/desktop.md` → "Picture-in-picture (PiP)". `tests/philogg.regression.test.js`: new **Group 182** covers the page-side half jsdom can see (`philoggSetPip` flipping `state.pipActive` + `html.pip-mode`, the `html.pip-mode` chrome-hide CSS list as a tripwire, and `jumpAfterPip` routing direct vs. through a stubbed `window.philogg.exitPip`); real window geometry and the injected buttons need `cd desktop && npm run tauri dev`.

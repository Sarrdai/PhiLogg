- **Wildcard-pattern syntax simplified: `[value:TYPE]` → `[*:TYPE]`** (this session, 2026-09-08, person-requested). The two separate placeholder vocabularies for "match anything" (`[*]`) and typed extraction (`[value:float]`, `[value:int]`, ...) are unified under one `*`-prefixed family: `[*]` still means "anything", and typed placeholders (with their optional numeric conditions, e.g. `[*:float>=10]`) now use `[*:TYPE]` instead of `[value:TYPE]`. Purely a literal-string change in `EXTRACT_TOKEN_RE` (`philogg.html`) — the alternation still structurally distinguishes the bare wildcard from a typed one, only the prefix text moved from `value:` to `*:`; `compileExtractPattern`, `parseValueConditions`, `valueSatisfiesConditions`, `wildcardMatch`, and the condition grammar (`VALUE_CONDITION_*`) are untouched. No release has shipped yet, so this is a straight replacement with **no legacy `[value:...]` alias** — old patterns typed as `[value:float]` are no longer recognized as wildcard tokens. Updated everywhere the old syntax appeared: the filter popup's placeholder text/token-chip tooltips, `insertTokenAtCursor`, `buildNumericExtractPattern`'s auto-generated patterns, in-code comments, `docs/filters.md`, `docs/extraction-and-plotting.md`, `docs/ui-concept-*.md`, `docs/ui-implementation-plan.md`, `PROJECT.md`, `README.md`, `FEATURE_BACKLOG.md`, `tools/log-simulator.html`, `homepage/index.html`, and the SVG sketches under `docs/images/`. `tests/philogg.regression.test.js`: every `[value:...]` pattern literal across the suite updated to `[*:...]` (mechanical, no behavioral test changes).

- **Fixed: Link dialog's "before" + "Enforce chronological order" always produced an empty result** (this session, 2026-09-08, person-reported bug). Not a bug in `linkOrderEnforced`'s monotonic-timestamp evaluation itself (`getEntriesFromBaked`/`getEntries`, unchanged, Group 22's semantics stay pinned) — the option is trivial for a single-direction hop chain: an all-"before" chain (including the common single-hop case) always fails the non-decreasing check and returns empty, an all-"after" chain always passes it and is a silent no-op. It's only meaningful once a chain mixes "before" and "after" hops. Fix is dialog-side gating in `philogg.html`: a new `updateLinkOrderEnforceAvailability()` disables + unchecks `#linkOrderEnforceInput` (never leaving a stale checked-but-disabled state) and shows a new `#linkOrderEnforceHint` explaining why, whenever the current `linkHopRows` directions aren't diverse (`dirs.length >= 2 && new Set(dirs).size > 1`). Called from `renderLinkHops()` on (re)build and from a `change` listener added to every hop's `.link-hop-dir` `<select>`. `tests/philogg.regression.test.js`: new **Group 190** — single hop disables with hint visible; two same-direction hops stay disabled; switching to mixed directions enables and hides the hint; reverting to same-direction while checked auto-disables and auto-unchecks. `docs/filters.md` "Opt-in options: order enforcement & exclusive matches" updated with the new gating behavior. **3710 passed, 3 failed** (`cd tests && npm test`) — the 3 failures are pre-existing `embedded:` round-trip failures unrelated to this change, reproduced independently of it.

- **Filter-tree icons now match the row-action button that would create each filter** (this session, 2026-09-08, person-requested). Previously all three time-filter shapes (legacy `"after"`/`"before"`, unified `"timerange"`) shared one generic clock icon (`ICON_CLOCK`) in the tree, regardless of whether the filter only bounds one side or is a real from-to range — while the `#viewBar` row-action buttons that create them ("Before"/"After"/"Time range") already had three distinct, more informative icons. New `timeFilterIcon(node)` helper (`philogg.html`, reuses the existing `timeRangeOfNode` normalizer so legacy and unified node shapes are handled identically) picks between three new icon constants — `ICON_TIME_BEFORE`/`ICON_TIME_AFTER`/`ICON_TIME_RANGE` — whose SVG paths are the exact same ones `VIEWBAR_ROW_ACTIONS` uses for "Before"/"After"/"Time range", based on which of `{from, to}` is set. `nodeIconHTML`'s time-filter fallback now calls this helper instead of returning `ICON_CLOCK` directly. Also fixed along the way: `idset` filter nodes (built from "Create filter from plot view") had no case in `nodeIconHTML`'s switch at all and silently fell through into the same generic clock despite not being a time filter — they now get their own new `ICON_CHECKLIST` icon. Plain-text (`ICON_FILTER`, funnel) and extraction-wildcard text filters (`ICON_TABLE`, table — already matching the "Extract" row-action button, whether the wildcards came from that button or were typed by hand) were already correct and untouched, as are the other filter types with no dedicated row-action button (`level`/`and`/`or`/`link`/`context`/`countContext`/`bookmarks`/`notes`). `tests/philogg.regression.test.js`: new **Group 192** covers all five icon cases (before/after/range/legacy-equivalents/idset) plus a sanity check that text/extraction icons stay distinct and unchanged. `docs/ui-and-views.md` updated (Visual language + Tree interactions sections).

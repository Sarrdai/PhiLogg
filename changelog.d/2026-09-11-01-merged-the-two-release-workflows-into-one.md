- **Merged the two release workflows into one shared build with two entry points: "Build Tester Files" (artifacts only) and "Build Release" (same builds, also published as a GitHub Release)** (this session, 2026-09-11, person-requested). Previously `release.yml` published only `philogg.html` and `desktop-release.yml` only published desktop installers, each always creating its own GitHub Release. Replaced both with `.github/workflows/build-tester-files.yml` and `.github/workflows/build-release.yml`: both share the same five `workflow_dispatch` checkboxes (`build_html` default on, `build_windows`/`build_windows_portable`/`build_mac`/`build_linux` default off) and the same stamp/strip/build steps for every variant, so HTML is now just another selectable variant alongside the desktop ones instead of always being built via a separate workflow. `build-tester-files.yml` uploads each selected variant via `actions/upload-artifact` and creates no release. `build-release.yml` runs the identical builds but publishes them together under one GitHub Release tagged `build-<short-sha>` (a `prepare` job creates the release up front so `build_html`/`build_desktop` can each just upload into it). Which branch to build from is picked via the workflow's own built-in branch selector in the Actions UI (`workflow_dispatch` already supports this, no extra input needed). `README.md`, `PROJECT.md`, `docs/desktop.md`, `docs/ui-and-views.md`, `desktop/README.md`, `philogg.html`, `scripts/strip-comments.js` and `tests/philogg.regression.test.js` updated to reference the new workflow files/names. No `philogg.html` runtime behavior changed, so the regression suite was not run.

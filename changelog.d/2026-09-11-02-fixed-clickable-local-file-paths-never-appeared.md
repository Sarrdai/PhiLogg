- **Fixed: clickable local file paths never appeared to work — no visible cue before verification, and verification depended on a fragile hover-timing window** (this session, 2026-09-11, person-reported: built a portable installer from this branch, opened a real log with an absolute Windows path in a message field, hovered it for over a second — no popup, no visible change at all). Code review found no functional bug in the regex, the Tauri command wiring, or the event-delegation logic, but two real design gaps: a `.fp-candidate` span had **zero** CSS before verification succeeded, making a detected path 100% indistinguishable from plain text — so there was no way to tell "nothing was detected" apart from "the existence check silently failed"; and the entire feature depended on a single hover-triggered async round-trip (180ms debounce + IPC call) succeeding while the cursor happened to stay put. Fixed both: (1) `.fp-candidate` now gets a dim, muted dotted underline immediately on render, in every build, independent of verification — `.fp-verified` upgrades it to the full accent-colored link look once confirmed. This makes the feature self-diagnosing on a rebuild: no underline anywhere means detection itself isn't running; a dim underline that never upgrades means verification (the Tauri bridge, or the path just not existing) is the broken half. (2) Verification moved from hover-triggered to **eager, cached, once per unique path**: new `verifyVisibleFpCandidates()`, called at the end of `renderVisibleRows()`, resolves every newly-seen candidate path right after render (`fpPathCache`, deduped via `fpPathPending` so an in-flight check is never started twice) instead of waiting for a hover to survive its debounce window — hovering an already-resolved span now just opens the popup from the cache, with no IPC call and no timing dependency at all. Also fixes redundant IPC calls for a path that recurs across many rows in one file (the common case, e.g. the same config path logged on every save) — now checked exactly once instead of once per hover. `tests/philogg.regression.test.js` Group 199 extended: 199b now asserts the underline renders immediately (computed style) with no `window.philogg`; 199c asserts verification happens with zero `mouseover` dispatched and exactly one `pathExists()` call, including after a subsequent hover; new 199d pins the per-path dedupe (two rows, same path, one call); 199e (was 199d) keeps the nonexistent-path case. `docs/desktop.md` updated. **3848 passed, 0 failed** (`cd tests && npm test`).

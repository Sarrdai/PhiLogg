- **ZIP sources: fixed an opened log entry not nesting inside its zip's container, plus inline in-app viewers (syntax-highlighted text, pan/zoom/reset image viewer) for common non-log entry types, plus hide the tab bar when nothing log-shaped is active** (this session, 2026-09-11, person-reported bug + feature request). (1) **Bugfix**: an opened zip log entry rendered as a detached top-level file instead of nested inside `renderZipSection`'s own box, the way an opened folder-watch file stays nested via `node.folderId`. Root cause: `openZipEntry`/`loadFileDescriptors` never tagged the resulting node with anything identifying its zip origin. Fixed with a new, separate `node.zipId` field (not `node.folderId` — every consumer of that field assumes a real, reconnectable `state.folders` entry, which a never-persisted zip source doesn't have), set on the node from its very first queued-placeholder render via a new `zipId` field on the `loadFileDescriptors` descriptor; `renderZipSection` now mixes a real tree row (for an entry matched by `node.zipId`+name) in among its inert placeholder rows, same pattern `renderFolderSection` already uses, and `renderTree` skips any `node.zipId` row the same way it already skips `node.folderId` ones. `node.zipId` is deliberately never persisted, so a session-restored zip-opened file just becomes an ordinary top-level file next reload. (2) **Inline viewers**: a non-log entry of a common type now renders in the main content area (`#inlineViewerWrap`) instead of always going to the pre-existing OS-open/browser-tab fallback (`openZipEntryExternally`) — `.txt`/`.xml`/`.json` get a text viewer (`.json`/`.xml` with new lightweight regex-based token highlighting, `highlightJsonText`/`highlightXmlText` — no generic syntax highlighter existed anywhere else in the app to reuse), `.jpg`/`.jpeg`/`.png`/`.tiff`/`.tif` get an image viewer with pan/zoom/reset/drag-to-select-a-region-and-zoom, modeled directly on Plot View's own interaction (same zoom-factor constants, same `.plot-drag-rect` overlay class, same `plotZoom`/`plotLastRender`-shaped state under new names `imgZoom`/`imgLastRender`) rather than spliced into Plot View's own data-extraction-coupled rendering code. Every other extension keeps the existing external-open behavior unchanged; checked whether folder watch or plain drag/drop ever hand a non-log file to an "open externally" mechanism (they don't — this stays zip-specific, no generalized "open any file" system was built). Desktop's `open_extracted_entry` Rust command is untouched — still used for every non-inlined type. (3) **Tab bar**: `#breadcrumbBar` (the thin strip above the main content area) now hides whenever nothing log-shaped is active — no files loaded at all, or a non-log inline viewer is the active content — instead of always staying visible (empty) as before. `tests/philogg.regression.test.js` **Group 199** extended with **199h** (nesting fix: `node.zipId` tagging, nested render, return-to-placeholder on close), **199i**/**199i-2** (inline text viewer + tab-bar-hidden + JSON/XML tokenizers), **199j** (inline image viewer); **199f**/**199g** updated to non-inline-viewable fixtures (`.mp3`/`.pdf`) since their original `.png`/`.txt` fixtures now hit the new inline viewers instead of the external-open paths those tests exercise. `docs/persistence-and-sync.md`'s "ZIP sources" section updated.

- **ZIP inline viewers, two refinements: a line-number gutter + click-to-highlight for the text viewer, and unifying non-log entries' open/close/select lifecycle with a log file's own tree row** (this session, 2026-09-11, person-requested follow-up to the entry below, screenshot-referenced for the desired functionality only, not its visual style). (1) **Line-number gutter**: the inline text viewer (`.txt`/`.xml`/`.json`) now renders each line as its own `.itv-line` row — a non-selectable `.itv-line-num` gutter cell (`user-select:none`, plus a genuinely separate DOM element from the text so a selection/copy from the content column never includes the numbers) and an `.itv-line-content` cell. This is a **new**, small, consistently-styled addition rather than a reuse of an existing mechanism — checked first, per the plan: the main log view (`renderVisibleRows`) has no literal per-line-number column at all to copy (it's a field-column table — time/level/thread/location/method/message — not line-numbered free text), so there was nothing to reuse there. Clicking a line toggles a click-to-highlight class (`.itv-line-selected`, reusing the app's existing selected-row look — `.log-row.selected`'s inset accent `box-shadow`), tracked on `state.inlineViewer.selectedLine`; the click listener is attached ONCE to the stable `#inlineTextViewer` container (event delegation), not per-line, since `renderInlineTextViewer` rebuilds every line's DOM node via `innerHTML` on each call — the same DOM-identity trap CLAUDE.md's "`renderVisibleRows()` rebuilds nodes" gotcha describes, sidestepped the same way. `.json`/`.xml` tokenizing now runs **per line** rather than on the whole text (a match spanning a raw newline would otherwise leave an unclosed `<span>` dangling into the next line's markup). (2) **Lifecycle unification**: a non-log entry's own row (`renderZipEntryRow`) now carries the exact open/close/select mechanics a log file's real `.tree-row` already has — `zip.inlineViewers` (a new `Map<entryName, viewerObject>` on each zip) stands in for "already has an open node," so a plain click on an already-opened row re-selects it (no re-extraction) and its own new `.tree-del` ✕ closes it; `#inlineViewerCloseBtn`, the separate close button that used to live on the viewer itself, is gone. New CSS states `.zip-entry-opened` (not grayed, once opened) / `.zip-entry-active` (the accent highlight, only for the entry actually shown) mirror an opened-but-not-selected vs. active log file's tree row. Selecting a real tree row, or opening a brand-new zip log entry, now also clears `state.inlineViewer` (a latent bug: `renderMainView` gave the inline viewer unconditional priority, so a previously-open non-log viewer could keep hiding a newly-opened log file's content). `docs/persistence-and-sync.md`'s "ZIP sources" section updated. `tests/philogg.regression.test.js` **Group 199** extended with **199k** (gutter structure + numbers-vs-content separation), **199l** (click-to-highlight toggling + surviving a re-render via the delegated listener), **199m** (grayed/opened/active row states, row-driven open/re-select/close, opening a log entry clearing a previously-active non-log viewer); **199i** updated to check `.itv-line-content`'s text instead of the whole viewer's `textContent` (which now also picks up the gutter number).

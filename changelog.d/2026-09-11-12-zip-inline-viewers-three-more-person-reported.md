- **ZIP inline viewers, three more person-reported bugfixes (screenshot-referenced): a multi-line copy no longer truncates its last line, switching to a non-log entry now actually deselects the previously-active log file, and the minimap now hides while a non-log entry is active** (this session, 2026-09-11, follow-up to the two entries below). (1) **Multi-line copy truncation**: `itvContentOffset` (the `copy` handler's Range-boundary→character-offset resolver) special-cased a boundary landing outside `.itv-line-content` by clamping to 0 or the line's full length via `Node#compareDocumentPosition`'s `PRECEDING` flag — wrong whenever the boundary's element is an ANCESTOR of `.itv-line-content` rather than an unrelated sibling, since `compareDocumentPosition` sets `PRECEDING` for a containing node the same as for a textually-preceding one. A real drag ending past the last character of a selected line commonly resolves to exactly that shape — `(lineEl, lineEl.childNodes.length)`, the `.itv-line` DIV itself, one level above `.itv-line-content` — so the old code always took the "clamp to 0" branch there, truncating the last selected line to empty regardless of how far into it the drag actually went, and reproduced with the person's own report's XML shape (indented closing tags each on their own line). Fixed by dropping the special-case branch entirely: `Range#setEnd(container, offset)` repositions a boundary correctly regardless of how `container` nests relative to `contentEl` (ancestor, descendant, or a sibling like the line-number gutter), so the one general path now handles every case. (2) **Switching to a non-log entry didn't deselect the log file**: opening/re-selecting a non-log inline-viewer entry, and Alt+Up/Down landing on one, only ever set `state.inlineViewer` — never cleared `state.activeId` — even though the reverse direction (selecting a real tree row, or opening a brand-new zip log entry) already clears `state.inlineViewer` as part of the same transition. `state.activeId` stayed pointed at the previously-active log file, so its tree row kept the `active` class (`renderNode`'s `id === state.activeId` check) after switching away from it. All three call sites now go through a new shared `activateInlineViewer(viewer)` helper (`state.activeId = null; state.inlineViewer = viewer;`) instead of assigning `state.inlineViewer` directly, so a future fourth call site can't reintroduce the same gap. (3) **Minimap stayed visible after switching, and even after closing the log entirely**: `renderMainView`'s `state.inlineViewer` early-return branch (the same one that already hides `#breadcrumbBar` — see the entry two below) never touched `#timelineMinimap` at all, so whatever visibility it had before switching just stuck; since that branch returns before the `!hasFiles` code further down (the only other place hiding it) ever runs, the minimap also stayed visible after the log file that was open before the switch was closed outright while the non-log viewer remained active. Fixed by adding the same `classList.add("hidden")` to that branch, mirroring `#breadcrumbBar`'s existing gating — and, since fix (2) makes closing the log file behave identically to it never having been the active node, this required no separate condition. `docs/persistence-and-sync.md`'s "ZIP sources" section updated. `tests/philogg.regression.test.js` **Group 199**: new **199t** (a multi-line copy stays correct when a Range boundary resolves to the `.itv-line` DIV itself, in both drag directions), **199u** (all three "becomes active" paths — open, re-select, Alt+Down — clear `state.activeId` and the previous log's tree-row `active` class), **199v** (the minimap hides once a non-log entry is active and stays hidden after the log file open before the switch is closed entirely).

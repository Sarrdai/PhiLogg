- **Inline text viewer: rearchitected for reliable native copy/select, plus collapsible JSON/XML sections** (this session, 2026-09-12, person-reported: copy/select of leading whitespace or tabs was unreliable, the viewer felt "stitched together" from many elements). `renderInlineTextViewer` now builds each line as a single inline `<span class="itv-line">` holding the raw line text directly (inside one `<pre>`), instead of a block `<div>` wrapping separate `.itv-line-num`/`.itv-line-content` spans. Line numbers are now a CSS `::before` counter — generated content, never a DOM text node — so they can never enter a selection or `copy` event; this removes the need for the old `copy` event handler and its `itvContentOffset` Range-offset helper entirely, since native browser select/copy is now correct by construction (byte-identical to the source, including leading whitespace/tabs). Added `findJsonFoldRanges`/`findXmlFoldRanges` (lightweight bracket/tag-matching scans) + `buildFoldTree`/`renderFoldNode` to make multi-line JSON/XML structures collapsible via a small `.itv-fold-toggle` glyph on the opening line — pure CSS collapse/expand, no re-render. See `docs/ui-and-views.md` → "Inline text viewer" for the full writeup. Regression coverage: GROUP 199 (`tests/philogg.regression.test.js`) — 199i/199k/199p/199r/199s rewritten for the new structure, 199t/199x removed as dead code (they only existed to pin down the now-deleted copy handler's Range-boundary edge cases), 199y added for fold behavior.

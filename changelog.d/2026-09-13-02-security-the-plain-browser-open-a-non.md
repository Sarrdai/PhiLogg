- **Security: the plain-browser "open a non-log ZIP entry externally" fallback can no longer execute archived HTML/SVG in PhiLogg's origin** (this session, 2026-09-13, person-requested security audit follow-up). When a non-log, non-inline-viewable ZIP entry is opened in the plain browser build (no Tauri wrapper), `openZipEntryExternally` builds a `Blob:` URL and `window.open()`s it in a new tab. A `Blob:` URL inherits PhiLogg's *own* origin, so for an active-content type (`.html`/`.htm`/`.xhtml`/`.xht`/`.svg`) the archived file's scripts would run against PhiLogg's `localStorage` (persisted sessions/filters/themes) — a stored-XSS/exfiltration vector triggerable by opening a crafted archive. New `safeTabBlobMimeType(name)` (added next to `guessZipEntryMimeType`) serves exactly those extensions as `text/plain` — the tab shows inert source instead of executing it — and delegates every other type to `guessZipEntryMimeType` unchanged, so images/PDF/text still render inline and unknown types download. Nothing legitimate is downgraded: images route to the in-app inline image viewer well before this path, and `.svg` is deliberately not among the inline image extensions. The Tauri desktop build never reaches this fallback (it hands raw bytes to the OS via `openExtractedEntry`), so the change is browser-build-only. The rest of the untrusted-input surface was audited in the same pass and found already sound: log/message rendering is consistently `escapeHtml`-escaped (with `linkifyPaths` splitting on tags and operating only on already-escaped text), session/filter/theme imports use `JSON.parse` (no `eval`/`new Function`), XML previews go through `DOMParser` with `application/xml` (no script execution) and an escaping tokenizer, and the inline image viewer's `<image href>` only ever gets a base64 `data:` URL (no attribute breakout) restricted to raster extensions. `tests/philogg.regression.test.js` **Group 207**: `safeTabBlobMimeType`'s MIME mapping (script-capable → `text/plain`, everything else passes through, including `.png`→`image/png` as a guard against a future refactor routing the image viewer's Blob through it), and an end-to-end drive of a `.svg` entry through the real dblclick → Blob fallback (asserting the Blob is `text/plain` and the embedded `<script>` never executed). See `docs/persistence-and-sync.md` → "Any other entry". Full suite: **4168 passed, 0 failed**.

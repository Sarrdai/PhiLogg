- **Per-file clock offset** (this session, 2026-09-13, implements FEATURE_BACKLOG.md #29). A manual clock correction for a single (non-merged) source file, reachable from its tree-row context menu ("Adjust clock…"). Approach (a): the signed-ms delta is **baked into every `entry.ts`** of that file (not applied lazily at read time), and the cumulative amount is stored on the file node as `node.clockOffset` (default 0) so it can be shown, re-edited and undone. `entry.raw`/`entry.tsRaw` are deliberately left untouched — every time display reads `formatTime(e.ts)`, so shifting `ts` alone updates the whole UI, while the session cache (which rebuilds a file's text from `entry.raw` and re-parses it) keeps the original raw timestamps and re-applies `node.clockOffset` on restore. The dialog (`#clockOffsetDialog`, following `docs/ui-standard.md`: segmented `.assert-mode-btn` mode toggle, `.settings-row` rows, `.btn-mini-secondary`/`.btn-mini` footer, one-line hints, theme vars only) offers two interpretation modes — **Difference** (a forgiving signed delta: `+1500` ms, `-2s`, or `±HH:MM:SS.mmm` — see `parseClockDelta`) applied additively to all entries, and **Start time** (a datetime input pre-filled with the file's current first `ts`; effective delta = desiredStart − currentFirstTs) — with a **live preview** of the first and last log line each as old → new. **Merged-file gotcha**: `mergeFiles` reuses a source file's entry *objects* by reference, so shifting the source's `entry.ts` also moves those entries inside any merged file that contains them — `applyClockOffset` therefore re-sorts every merged root file and drops its `_orderIndexMap` (`invalidateOrderIndexMap`) after a shift, then `invalidateAllCaches()` (a rare structural-equivalent change); the source file's own uniform shift preserves its order, so its own array/order-map stay valid untouched. **Undo/redo**: a new `"clockOffset"` action captures the applied delta and re-applies the *inverse* on undo (a naive snapshot can't capture the old `ts`, since `snapshotSubtree` copies entries by reference), so apply→undo→redo round-trips exactly. `node.clockOffset` is threaded through every file-node persistence carrier: the session cache (`persistFileNode`/`restoreSessionFromCache` — re-applied to the re-parsed entries, since the cached text keeps the original raw timestamps), undo of a file delete (`snapshotSubtree`/`restoreSubtree`), and **session export/import** (`buildSessionExport` writes it; `applyImportedClockOffset` re-applies it to the tier-matched importer file — as the difference from that file's current offset, before any timestamp-based bookmark/note re-anchoring — so the imported file's first/last timestamps match what was exported). `tests/philogg.regression.test.js` **Group 208** (208a difference mode + parser + menu item + accumulation;

- **Folder-watch minimap for picking which files to load/merge** (this session, 2026-09-14, implements FEATURE_BACKLOG.md #64). Clicking a watched folder's own title (`.folder-watch-name`, `selectFolderContainer`) now switches the main content area to a per-file time-range timeline for that folder instead of any single node's log view — a new `state.folderView`, dispatched in `renderMainView` the same way `state.inlineViewer` already is (mutually exclusive with it). The minimap shows exactly the files `folder.files` currently lists (so a folder narrowed by a glob pattern or "show newest M" shows the same subset there, no separate filtering step needed) as one horizontal bar per file on a shared time axis, stacking where spans overlap. Each bar's range comes from `probeFileTimeRange` (added last session) for a file that isn't open yet, or straight from its real entries once it's loaded — cached on the folder's own file record as `rec._range`, invalidated by `mergeScannedFiles` whenever a file's mtime changes underneath it. Two ways to pick files, then a **Load** button: multi-selecting individual bars loads each file with no merge; dragging a time window loads every file overlapping it, fully merges them (`mergeFiles`), and applies a `timerange` filter matching the exact dragged window to the result (same `createFilterNode` call the log minimap's own drag-select uses) — so the merge opens already filtered to what was drawn. Folder-only: a ZIP source's entries are deflate-compressed, so there's no cheap head/tail read the way a real folder file gets — a new backlog entry (#65) captures the deferred ZIP variant instead. `tests/philogg.regression.test.js` **Group 204**: `probeFolderFileRange`'s caching and its `mergeScannedFiles`-driven invalidation on mtime change, an already-opened file's range coming from its real entries instead of a re-probe, the `folderView` main-view dispatch (shown on title click, cleared by any real node activation, falls back when the folder is removed while showing), and the Load button's two modes (individual bars → no merge; a dragged window → merge the overlap + a matching `timerange` filter, a non-overlapping file excluded).

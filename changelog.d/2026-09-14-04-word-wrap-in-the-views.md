- **Word wrap in the views** (this session, 2026-09-14, implements FEATURE_BACKLOG.md #68). Two independent, session-cache-persisted soft-wrap toggles, each in its own view's toolbar, both distinct from the existing multiline-message toggle (multiline renders literal `\n` breaks; word-wrap soft-wraps a single long line so it no longer needs horizontal scrolling — the two combine freely). (1) **Log view** (`state.wrapMessages`): a `.toggle-wrap` button in both log toolbars (`#filteredToolbar` and `#contextToolbar`) soft-wraps the message column (`.col-msg`) instead of truncating/scrolling. It also governs the **Entry Detail** message wrap, since the detail panel shows the selected log entry — off (default) the detail scrolls horizontally, on it wraps. (2) **Text View** (`state.wrapTextView`): its OWN `#itvWrapBtn` toggle in the inline-viewer toolbar (now shown for any `.txt`/`.xml`/`.json`, with Pretty Print still JSON-only). Line numbers are a CSS `::before` counter on each `.itv-line` (one per LOGICAL source line), so a wrapped display line shares its line's number and never increments it. **Virtualization**: the log view's wrap is folded into the same exact-height offsets machinery the multiline feature established — `.wrap-messages .col-msg` uses `word-break:break-all` deliberately, so each visual line packs to exactly the message track's character capacity and a row's wrapped line count is `ceil(chars / columns)`, computable from data alone (`messageWrapLines`/`wrapColsForBody`, biased one column conservative so a row can only ever over-allocate, never clip) — no per-row DOM measurement, no scroll drift. Both flags round-trip through the session cache's `meta.settings` (same tier as `multilineMessages`).

- **Bugfix: "Syntax highlighting" set to "Follow app theme" didn't change when the app theme changed** (this session, 2026-09-14, person-reported: "Mit 'Syntax highlighting' eingestellt auf 'Follow app theme', wechselt die Darstellung nicht, wenn man das App Theme ändert"). Root cause: `applySyntaxScheme()`'s follow-theme branch was a pure no-op, relying entirely on the CSS cascade to pick up `--syntax-*` from the active theme — but only Dark and Light declare their own `[data-theme]` `--syntax-*` block in CSS (`:root` / `:root[data-theme="light"]`); the four Catppuccin flavors don't, so under follow-theme they all silently fell back to Dark's colors and switching the app theme to/between any of them never visibly changed the highlight colors, even though a matching curated pendant already existed for each in `BUILTIN_SYNTAX_SCHEMES`. Fixed by having `applySyntaxScheme()` fall back to the `BUILTIN_SYNTAX_SCHEMES` entry matching the active theme id (`currentThemeId()`) when follow-theme is chosen and the active theme is a built-in one — applied inline exactly like an explicitly-picked scheme. A custom app theme (no matching built-in id) is unaffected: still the pre-fix cascade (its own optional `syntaxColors` block, else the `:root` defaults). `tests/philogg.regression.test.js` **Group 210a** updated: its old assertion that Catppuccin Mocha "cascades to the :root (dark) defaults" under follow-theme encoded the bug itself and is replaced with checks that every Catppuccin flavor resolves to its own pendant colors, and that switching Mocha → Latte actually changes `--syntax-tag`. See `docs/ui-and-views.md` → "Independently selectable scheme". Full suite: **4412 passed, 0 failed**.

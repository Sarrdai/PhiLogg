  1. **CI couldn't open the release PR at all** — `##[error]release-please failed: GitHub Actions is not permitted to create or approve pull requests`. Root cause: the repo's `Settings → Actions → General → Workflow permissions → "Allow GitHub Actions to create and approve pull requests"` toggle, off by default and independent of the `permissions:` block already declared in the workflow YAML. The person enabled it directly in GitHub's UI (no code fix needed/possible from this session).
  2. **`PHILOGG_VERSION` silently never got updated.** The `// x-release-please-version` marker comment was placed on the line ABOVE the constant; release-please's generic extra-file updater only replaces a value on the *marker's own line*, so it found nothing there and quietly did nothing — the run advanced `.release-please-manifest.json` and all three desktop version fields to `0.2.0` while `philogg.html`'s own `PHILOGG_VERSION` stayed stuck at `0.1.0`.   3. **`release-please-config.json` was missing `"skip-changelog": true`.** Without it, release-please's default behavior applied its own auto-generated release-notes block on top of this hand-written `CHANGELOG.md` — renaming its `# PhiLogg — Changelog` title to a bare `# Changelog`, prepending a mechanically-generated `## [0.2.0] ...` section (a raw commit-message dump, including the 100+ pre-convention historical commits release-please happened to also parse as conventional), and demoting the original title/intro to a stray `## PhiLogg — Changelog` sub-heading further down.

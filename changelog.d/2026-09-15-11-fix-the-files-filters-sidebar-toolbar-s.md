- **Fix: the Files & Filters sidebar toolbar's "Edit filter…" button (and every other action on it) did nothing when clicked** (this session, 2026-09-15, person-reported: "Der Edit Filter Button löst aktuell keine Aktion aus. Erwartungshaltung: Filter Edit Popup öffnet sich"). Root cause: `#sidebarToolbar`'s click listener dispatched to `handleSidebarToolbarActionClick` without calling `ev.stopPropagation()` first, unlike the pre-existing `[data-row-actions]` delegated listener it was modeled on (`#viewBar`/the per-view toolbars). The same click that opened `#filterPopup` (via `editFilterNode` → `openEditFilterPopup`) kept bubbling up to the document-level "click outside a popup closes it" listener, which saw a click outside the popup that had *just* opened and closed it again in the same tick — an instance of `CLAUDE.md`'s own "stopPropagation on any click handler that opens a popup" gotcha, missed for this one new listener when it was added. One-line fix: `ev.stopPropagation()` added to `#sidebarToolbar`'s click listener. `tests/philogg.regression.test.js` **Group 222**: a real, bubbling `fireClick()` on the actual "Edit filter…" button confirms `#filterPopup` stays open afterward (pre-existing Group 220i only ever called `handleSidebarToolbarActionClick` directly, which never bubbles and so could never have caught this class of bug) — confirmed to actually fail without the fix.

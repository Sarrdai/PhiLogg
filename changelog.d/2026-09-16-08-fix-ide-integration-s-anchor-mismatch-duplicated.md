That confirmed two things the original design got wrong. **(1) Anchor semantics**: the very first design discussion's own example had the solution sitting *directly inside* the anchor folder (`...\Code\Projects\myProject.sln`) — i.e. the anchor **is** the local solution/project directory, not its parent — but `resolveIdeSourcePath` kept the anchor segment itself as part of the relative path it joined onto that directory. For Visual Studio this only happened to produce the same total string as before when the anchor occurred exactly once (never actually exercised on a real machine yet); for Rider it produced `Projects/MyCompany.Controller.Scripting/ScriptingService.cs` where the confirmed-working link needed `MyCompany.Controller.Scripting/ScriptingService.cs` — no `Projects`. Fixed by joining only what comes AFTER the anchor match, never the match itself. **(2) A real pattern, not just a folder name** (person-requested: "an actual pattern like used in other places of the app, so it could handle something like 'Projects' being twice within the full path"): the anchor setting ("Path anchor pattern" now, was "Path anchor folder") is compiled by a new `compileIdeAnchorPattern` using the exact same `*`/`?` convention `compileGlob` already uses for folder-watch's file-to-format matching (`*` = any run of characters, `?` = any one character, everything else literal; a literal `\`/`/` in the pattern matches either separator) — reused rather than inventing new syntax — matched as a substring anywhere in the path (not anchored to a whole segment), so a longer pattern like `Code\Projects` can disambiguate a folder name that occurs more than once, where the old exact-segment "last occurrence wins" heuristic had no way to. **(3) Rider's line number is 0-based**, confirmed by the person's own report — `parseIdeLocation`'s 1-based line (matching Visual Studio's own `GotoLine` contract) is unchanged; `buildRiderUri` now subtracts 1 (clamped to 0) only when building the URI string. `tests/philogg.regression.test.js` **Group 230** reworked in place (not just extended): the motivating example with the corrected solution-directory understanding, a sanity check the anchor is never duplicated, a "tricky" fixture proving a bare anchor name picks the wrong (coincidental, deeper) occurrence while a longer pattern disambiguates correctly (either slash style), a `*` wildcard, and the exact real-world Rider path from this report confirming the excluded-anchor join; `buildRiderUri`'s cases updated for the 0-based line, including the exact reported "line 1 → :0" case. `docs/desktop.md` → "IDE Integration" updated in place for both the pattern convention and the 0-based line note.

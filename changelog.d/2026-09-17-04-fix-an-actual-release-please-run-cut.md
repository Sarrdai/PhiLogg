- **fix: an actual "Release Please" run cut `v1.0.0` instead of the intended `0.1.0` — a manifest value of exactly `"0.0.0"` is release-please's own "never released" sentinel and forces `1.0.0` regardless of `bump-minor-pre-major`** (this session, 2026-09-17, person-reported after watching it happen live: propose-release → merge → cut-release built and published a real `v1.0.0` GitHub Release with Windows/HTML assets — not the `0.1.0` the previous session's manifest reset was supposed to produce). Root cause confirmed against release-please's own source and a matching upstream report (googleapis/release-please#2087): the manifest's literal `"0.0.0"` isn't treated as "start bumping from zero," it's a hardcoded sentinel meaning "this component has never been released," and for that specific case release-please skips conventional-commit bump math entirely and defaults straight to `1.0.0` — independent of `bump-minor-pre-major`, which only ever affects *breaking-change* bumps pre-1.0, not this path. Person confirmed the intent explicitly: ordinary `feat:` commits bumping MINOR is fine, but nothing should cross `1.0.0` without an explicit, conscious decision. Fixed the supported way: `release-please-config.json`'s `.` package now carries `"initial-version": "0.1.0"`, which is exactly what release-please computes a first release to instead of the `1.0.0` default, with the manifest staying at the correct fresh-repo `"0.0.0"` sentinel. Recovery: `.release-please-manifest.json` and the four version files the erroneous release commit touched (`philogg.html`'s `PHILOGG_VERSION`, `desktop/package.json`, `desktop/src-tauri/tauri.conf.json`, `desktop/src-tauri/Cargo.toml` — plus `Cargo.lock`'s matching entry, which the release commit doesn't touch but had drifted to `1.0.0` too) rolled back from `1.0.0` to `0.1.0`/`"0.0.0"`. **The `v1.0.0` GitHub Release/tag itself still needs manual deletion** — no available tool exposes GitHub release/tag deletion, so this is a manual cleanup step before running `propose-release` again. `PROJECT.md` → "Release builds" gets a permanent "Gotcha" callout for this so it's never re-triggered by accident.

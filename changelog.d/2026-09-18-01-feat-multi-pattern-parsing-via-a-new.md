- **feat: multi-pattern parsing (FEATURE_BACKLOG.md #81) via a new "meta" log format, plus a "Sources" grouping/coloring feature for any merged file (this session, 2026-09-18, person-requested)**. Implements option (c) from #81's own discussion, chosen in full generic form: a third `LogFormat` mode, `"meta"`, alongside the existing `"pattern"`/`"regex"` — a meta-format carries no pattern/regex/tsFormat/levels of its own, only an ordered `targetFormatIds` list (≥2) naming other, ordinary formats to classify a file's lines against (`compileOneFormat`'s new `"meta"` branch is a defensive-only fallback; real files never reach it). `splitTextByMetaFormat(text, metaFmt)` classifies each non-blank line against every target's own already-compiled `isHeaderLine`, first match per line wins; a non-matching, non-blank line joins whichever target's stream most recently matched (the same continuation rule `parseLogTextAsync` already applies, just resolved per-stream before parsing starts); blank lines are dropped during the split entirely, never emitted into any stream — provably equivalent to today's single-format behavior, since `parseLogTextAsync`'s own loop already treats a blank line as a silent no-op. `loadMetaFormatText(name, text, metaFmt)` parses each classified stream as an ordinary transient file (reusing `addFile`/`parseLogTextAsync` unmodified), sorts each transient file's own entries by `ts` (a virtual syslog-block stream isn't guaranteed chronological on disk — the risk this pre-sort specifically guards against, since `mergeFiles`' disjoint-time-range fast path trusts each source's own order), then merges them via the existing, unmodified `mergeFiles`, renames the result to the physical filename, and removes the transient per-grammar vnodes (safe: `mergeFiles` already pushed the same entry objects by reference into the merged node first, so `deleteNode`'s `releaseEntriesFromIndex` purges nothing still live). Wired into both file-load entry points (`loadOneFileIntoTree`, `addFile`'s live-resolution branch) so drag-drop, the file picker, and folder-watch's on-demand open all pick it up automatically; folder-watch's minimap probe and windowed/partial loading explicitly decline a meta-format file in this first version (probe returns its existing "no range found" sentinel) rather than probing it wrong — no live-tailing either. Format Manager (Settings → Log format definitions) gained a third "Meta" mode button next to Pattern/Regex: an ordered target-format picker (add/reorder/remove, mirroring the existing level-order editor), a ≥2-targets save guard, and `removeLogFormat` now also blocks deleting a format still referenced as some meta-format's target. Three concrete formats from #81's own reference case (a log4net-style app grammar and an RFC 5424 syslog grammar, chat-uploaded this session — sample file + structural spec, previously flagged in #81 as needed before implementation) are seeded once via `loadFormatConfig()` (non-builtin, freely editable/deletable), with **no** filename rule attached — dormant until added by hand, per explicit request ("Only the Formats for now, i'll add a File association later"). Prerequisite fix found while wiring these up: the syslog sample's 6-digit fractional-second timestamps didn't parse at all — `DATE_TOKEN_FRAG.SSS` was hardcoded to `\d{1,3}`; widened to `\d{1,6}` and `parseTimestampGeneric` now normalizes the captured fraction by its own digit count (`Math.round(+frac * 10^(3-len))`) instead of treating it as a literal millisecond value (a bare `+"711324"` would have meant 711324ms — over 11 minutes' overflow into the wrong second — not `.711324s`); reduces to the exact previous behavior for a 3-digit fraction. Separately, and person-requested to generalize beyond just the new multi-pattern case: any merged file — the new meta-format auto-merge AND the pre-existing manual "Merge N files" bulk action alike — now gets an additive `node.sources` breakdown (`{id, name, color, count}` per source) and a matching `entry.sourceId` stamp on every copied entry (`mergeFiles`, both the disjoint-fast-path and chunked-copy paths), rendered as a new expandable **"Sources"** group directly under the merged file's own tree row (`renderSourcesGroup`/`renderSourceRow`, mirroring the ZIP/folder-watch "presentational container row" pattern — not real `state.nodes` entries), each source with its own color swatch reusing the existing highlight color-picker popup (generalized with an optional `onPick` callback, `openColorPicker`/`commitColorPick`, so a pick can land on `node.sources[i].color` instead of a filter node's `highlightColor`). `computeHighlightMap` gained a matching branch so a colored source's entries pick up the same gutter-marker lane filter highlights already use, composable with them. Session-only by explicit choice for this first version (no IndexedDB persistence — a session-cache restore of a merged file already reparses from scratch and loses this kind of state, same as the pre-existing "Merged-file gotcha") but threaded through `snapshotSubtree`/`restoreSubtree`'s file branch so an in-session delete+undo of a merged file doesn't silently drop its Sources group or any assigned colors. Known, accepted limitation: entries are shared by reference across merges, so merging an already-merged file's entries again overwrites `sourceId` on the same objects, making the earlier merge's own Sources coloring stale — not fixed here. New regression coverage: `tests/philogg.regression.test.js` GROUPs 232-239 (split/classification against the real reference sample, the disjoint-fast-path chronology risk specifically, the new Format Manager UI, degenerate split outcomes, `sources`/`sourceId` stamping for both merge origins, the Sources group's rendering/color/undo, and the SSS date-token fix) — 3 pre-existing Group 70 assertions updated for the new seeded-format count (1 default + 3 seeded → 4 initially, 5 after adding one more).

- **fix: two ways partial content could leak into view before a load actually finished — a meta-format merge's per-stream focus flicker, and the live-growing scrollbar exception — both closed, restoring "nothing renders until fully loaded" as an exception-free rule** (this session, 2026-09-21, person-reported: watching a meta-format load, the Filtered/Full/minimap view briefly showed each per-grammar stream's own already-complete content before settling on the merge, and separately, an ordinary single-file load could already show partial rows for the active view before it finished). Two independent causes, both against the same design principle documented in "File loading" in `docs/persistence-and-sync.md`. **(1)** `loadMetaFormatText` loads each stream via `addFile(..., placeholder)`, which internally calls `activateQueuedFileNode` — unconditionally flipping `state.activeId` onto that stream for the duration of its own read+parse. That stream's own natural-completion render (a real, full `render()`) then painted the main view with ONE grammar's complete content, before the loop's own trailing `state.activeId = merged.id` restored focus to the merge only at the very end. Fixed with a new `metaFormatSplitInProgress` flag, set for the loop's duration and checked in both `createFileNode`'s and `activateQueuedFileNode`'s `state.activeId` assignment — mirroring the pre-existing `sessionRestoreInProgress` guard those same two functions already had for an analogous "don't let a transient internal node steal focus" case. **(2)** A previous session's `updateLiveGrowingTotal` (called from `scheduleLoadRender`) deliberately kept `#tableSpacer`'s height and the visible table rows tracking an actively-loading node's live entry count, for the active view specifically — a real fix at the time for a large merge's stale scrollbar, but itself a narrow exception to the "nothing else updates live during a load" rule, and the second way partial content could show early. Removed outright (not narrowed further): `scheduleLoadRender` is back to only `updateLoadRowProgress`/`updateMergeLoadFraction`, no view/scrollbar write of any kind. Accepted tradeoff: `#tableSpacer`'s height (and `End`/`Ctrl+End`'s reach) goes back to staying stale until the load's natural completion, same as every other part of the view during a load — the scroll-cap/rescale mechanism (`detectMaxTableScrollPx`/`computeTableSpacerContentHeight`) that a later session added is unaffected, since it applies at every real render regardless. `docs/persistence-and-sync.md` → "File loading"/"Create-first loading" updated in place. `tests/philogg.regression.test.js`: new **Group 259** (the meta-format merge stays the active node throughout a real, multi-chunk two-stream split/load — checked synchronously right after the call, mid-loop, and once finished); **Group 254 REWRITTEN** (the spacer now stays stale across a load tick in all three of its former cases — active/background/level-filtered); Group 50's own scrollbar assertion flipped to match.

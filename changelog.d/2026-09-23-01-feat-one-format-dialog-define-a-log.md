- **feat: one format dialog — define a log format by example, with an automatic suggestion, marking, direct regex editing, auto-filled levels, a table preview, and an optional filename rule (this session, 2026-09-23, person-requested, built in three rounds: a "Set up from examples" wizard first, then preview double-click + undo/redo, then merging the old format editor into it)**. Settings → Log Formats → "Add format…"/"Edit" now open one large dialog on top of Settings. It replaces the old inline editor panel, whose Pattern field, single example field, and separate column editor are gone. `docs/ui-and-views.md` → "Format dialog" has the full mechanics.
  - **Examples**: paste (Ctrl+V or a Paste button), open a file, or drop a file anywhere while the dialog is open. A drop becomes example lines instead of loading, in the browser and under the desktop wrapper (`loadDesktopLocalFiles`).
  - **Automatic suggestion (new formats)**: the old `suggestPatternFromSample`, run on the first line with a timestamp, then generalized through the same derivation as hand marks. It shows up immediately as suggested marks plus the preview.
  - **Edit mode**: pasted examples are always shown against the format's **own** regex, never a silent new suggestion; the status line warns if it matches none of them.
  - **Re-suggest**: an explicit button that starts over from a fresh suggestion, also when editing, after an inline warning that the current marks, regex and timestamp format get discarded. A single Undo reverts it. A regex typed into the Regex field stands in above all of these.
  - **Marking**: pick a column (Time/Level fixed; Thread/Location/Method/custom removable, reorderable, renamable by double-click; Message last), then select its value in a line. The first mark on a line adopts that line's suggested marks, so correcting one column keeps the rest.
  - **Derivation**: after every change a whole-line regex is re-derived from all marked lines (`deriveFormatRegexFromMarks`): literal separators with space runs loosened to `\s+`, per-column character classes that generalize from few examples, the unmarked tail becoming Message, and an auto-detected `tsFormat` (`detectTsFormatFromValues`). Unmarked lines never feed it, which answers the stack-trace question; whether a line is a new entry is decided by the regex alone.
  - **Direct regex editing**: the Regex field is editable. Typing replaces the marks (re-shown as suggested marks from the typed regex), adds any new named group as a column, and is one undo step.
  - **Levels**: auto-filled from the captured level values for a new format. All-numeric values give Integer mode with one level per code, named after the code (`3` → `3`). Custom levels are renamable, and renaming onto an unused fixed name merges (`3` → ERROR keeps code 3). A hand edit switches auto-fill to append-only.
  - **Preview**: a table shaped like the log view, whose level badges follow the unsaved level list. Clicking a badge finds its level; double-clicking a row scrolls to and flashes its source example line.
  - **Undo/Redo**: covers marks, columns, lines, and regex typing (buttons, Ctrl+Z, Ctrl+Y / Ctrl+Shift+Z; whole-state snapshots, max 100).
  - **Filename rule**: the optional "Use for files matching" field adds a rule on save, appended last and never duplicated. It's pre-filled from a dropped file's name (`app-2026-09-23.log` → `app-*.log`), and the dialog lists the rules already using the format.
  - **Save**: always **Regex mode**. An existing Pattern-mode format is converted to its compiled regex, with the date's inner groups made non-capturing via `compileFormatPattern`'s new `plainDateGroups` option; the builtin default's Reset still restores its pattern. Only the columns the regex captures are saved. The examples + marks are stored as `fmt.sampleSetup`, so Edit reopens where it was left.
  - **Default-format examples** (person-tested with a real default-format file):
    - **Location**: the suggestion now claims a path-like field as Location. Before, it stayed literal, pinned the regex to one file, and matched nothing.
    - **Suggestion source**: it takes its column spans directly as virtual marks. Before, it re-ran the raw regex, whose `\S+` thread failed on `"(1) "` and silently fell back to the unusable raw suggestion.
    - **Closing quote**: it strips a message's closing quote.
    - **Multi-line messages**: text after a marked Message at the line end is now optional in the derivation (`"(?<message>.*?)(?:")?$`). A message whose closing quote sits on a continuation line (`… 'Evaluate` ⏎ `Evaluate with DirectInspect"`) no longer glues its entry onto the previous one.
    - **Continuation lines in the examples**: they now show a Message mark across the line (dashed, "continued from line N"), minus a quoted message's closing quote. Before, they stayed unmarked (person-reported).
    - **Closing quote on the continuation line**: it's dropped from the message instead of kept (person-reported follow-up). A header line whose closing quote is missing tags the entry as open (`messageWrapQuote`/`markOpenMessageQuote`). The shared `appendContinuationLine`, now used by the main-thread parser, the worker, tailing, and the preview, strips the quote from the line that closes it. `raw` stays verbatim.

- **feat: open gzip-compressed logs (`.gz`) (2026-09-25, FEATURE_BACKLOG.md #83)**. A rotated log like `app.log.1.gz` now opens transparently on every route: drag-drop, the file picker, the desktop wrapper's native pick/drop and file-association/"Open in PhiLogg" launch, folder watch, ZIP entries, `?url=`, and the format dialog's example loader. `docs/persistence-and-sync.md` → "gzip-compressed logs (`.gz`)" has the full mechanics.
  - **Detection and inflate**: gzip is detected by its magic bytes (`1f 8b`), not by extension. It's inflated with the native `DecompressionStream("gzip")`, the same Web API the ZIP path uses, so there's no dependency. The compressed input is streamed chunk by chunk, and the inflate drives the row's read-phase progress.
  - **Where it plugs in**: `loadOneFileIntoTree` (every file route) and `loadUrlIntoTree` inflate right before the text read, and so does the desktop session-cache "path" restore (`reopenLocalPathForRestore`).
  - **Native parsing (desktop)**: the Rust parser never sees gzip bytes as text. `parse_log_file` rejects a gzip file up front (`philogg_logparse::is_gzip`), before streaming anything, and every native caller already falls back to the JS read + parse, which inflates. So there is no Rust-side decompression and no new crate.
  - **Range reads**: the tail poll's one-time gzip check is a 2-byte read through `getPartialReadFile`. The minimap probe returns "no range" for gzip, and the windowed load falls back to a full load because it has no range.
  - **Names**: the node keeps its real name. `.gz`, plus a logrotate counter behind it, is looked through for format rules and folder-watch patterns (`fileNameGlobTest`) and for "is this a log?" (`isCompatibleFolderFile`, which also drives ZIP entry classification). `app.log.1.gz` counts as a log; `data.gz`/`.tar.gz` don't.
  - **Static only**: a gzip file is never tailed. No load or "path" restore attaches a tail, and `tailTick` drops one that a session restore or folder rescan reattaches.
  - **Picker filters**: `.gz` added to the `<input>` accept lists and the desktop `pick_files` filter.
  - **Desktop**: `.gz` launch arguments route like `.log`, the native folder listing is asked for `.gz`, and an opt-in `.gz` Explorer verb was added. `.gz` is deliberately not a `fileAssociations` entry. `docs/desktop.md` is updated.
  - **Tests**: new **Groups 284–285** (285d/e: the desktop native route with a stub that rejects gzip the way `parse_log_file` does, and the desktop "path" restore); crate unit test `gzip_magic_is_detected`. GROUP 272's tail-poll request count now includes the one-time 2-byte gzip check on a hand-attached (reattach-style) tail; load paths mark their own fresh tails as already checked, so a normal poll stays at two requests.
  - **Full suite**: **6056 passed, 0 failed**.

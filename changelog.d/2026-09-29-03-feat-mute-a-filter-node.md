- **feat: mute (disable) a filter node (2026-09-29, FEATURE_BACKLOG #14)**
  - A filter node can be muted: its result becomes its parent's result unchanged (`getEntries` returns `getEntries(node.parentId)` before the `_cache` check, so a toggle can never leave a stale cache), its children stay active and evaluate against it, NOT/colour/assertions/children are kept. Files and the locked Bookmarks/Sources nodes are not mutable; every other filter type is.
  - Controls: eye button on the tree row (right before the x, hover-reveal, always visible and warn-tinted while muted; the muted row is struck through and dimmed, the count shows the passed-through count in italics), Mute/Unmute in the sidebar toolbar (after Invert (NOT); the toolbar now has six buttons) and the tree context menu, `Mute`/`Unmute` in the multi-select bulk menu/toolbar (one undo step via the existing `batch` undo kind), and the rebindable `M` shortcut (`muteFilter`). New sprite symbols `i-eye` / `i-eye-off`.
  - A muted node is skipped where it would act as a view: `findExtractionAncestor` looks past it (no Table/Plot from a muted wildcard node), a muted link node shows the plain entry table (`isLinkNode`), `computeHighlightMap`/text-match highlighting ignore it.
  - `muted` is threaded through `cloneSubtree`, `snapshotSubtree`/`restoreSubtree`, `captureNodeFields`/`applyNodeFields`, `serializeFilterBranch`/`importFilterJson` and `serializeFilterTreeForCache`/`materializeCachedFilters`.
  - **Tests**: new **Group 321**; GROUP 220/221/319 (sixth toolbar button, `mute` in the bulk action list), the context-menu group ordering assertion and the bulk-action assertions in the baked-condition group updated.

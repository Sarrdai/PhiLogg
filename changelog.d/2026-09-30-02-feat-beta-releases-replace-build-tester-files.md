- **feat: beta releases replace "Build Tester Files"; portable zip no longer double-zipped (2026-09-30, person-requested)**
  - New `.github/workflows/beta-release.yml` (manual, `main` only): publishes a GitHub **pre-release** `v<next>-beta.N`, e.g. `v0.2.0-beta.3`. `<next>` is the version the next stable release will get (release-please's rule: `feat`/breaking → MINOR below 1.0.0, else PATCH), N counts up per target version. The version is only stamped into the build's checkout, so the app shows `0.2.0-beta.3`; nothing is committed, the manifest is untouched, release-please keeps versioning stable releases as before.
  - Stable and beta share one reusable build, `.github/workflows/build-release-assets.yml` (HTML, Windows installer, Windows portable → workflow artifacts); each caller's `publish` job attaches them only after every variant built. Asset names now carry the version (`philogg-<version>.html`, `PhiLogg-<version>.exe`, `PhiLogg-<version>_portable.zip`) instead of date/SHA; the SHA stays in `PHILOGG_BUILD`.
  - New `scripts/release-version.js` (`next-beta`, `stamp <version> <build>`) replaces the workflows' inline `sed`.
  - Variant selection: the Beta Release dialog has one checkbox per variant (HTML, Windows installer, Windows portable on by default; macOS `.dmg`, Linux `.AppImage` off). A stable release always builds all five (a merge has no dialog).
  - `build-tester-files.yml` removed; its macOS/Linux builds moved into the shared build. It also produced the double zip: it 7z-zipped the portable folder and uploaded that zip via `upload-artifact`, which zips again. The new build's portable zip is a file inside the artifact that `publish` unpacks before uploading, so releases get one zip.
  - The `philogg-portable` marker is written with one line of text instead of `touch`.
  - **Tests**: new **Group 340**; GROUP 271e and 218 updated.

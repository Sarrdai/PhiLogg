- **fix: one tree selection model + keyboard shortcuts scoped to the focused area (2026-09-30, person-reported)**
  - **Ctrl+C after clicking a filter copied the log line**, and Ctrl+click on a second filter after creating one did not include the active filter. Root causes: `state.activeId` and `state.multiSelect` were two selections (every creator/file load clears `multiSelect` while `activeId` stays set; Ctrl+click only toggled `multiSelect`), and a tree-row click deliberately left `focusRegion` at `"entries"`, where Ctrl+C prefers the log row; most other shortcuts ignored the region entirely.
  - **One selection**: `treeSelectionIds()` = `multiSelect` ∪ active node, used by every reader (row class, sidebar toolbar + multi mode, context menu, bulk actions, library target, mute shortcut). Ctrl+click extends/shrinks that whole selection; removing the active node hands "active" to the most recently added remaining one; the last selected node cannot be deselected. `.multi-selected` now mirrors `.active` (background, text, left border, icon colours), the inset box-shadow frame is gone.
  - **Focus-scoped shortcuts**: a capture `mousedown` on `document` sets `focusRegion` (`#sidebar` -> `"tree"`, `#content` -> `"entries"`); a tree-row click now sets `"tree"`. Tree-only: Ctrl+C/X/V of filters, Delete, F2 (node), Ctrl+E, M, Esc (selection + clipboard). Log-only (and only for a view actually shown, `logKeysActive()`): row/table Ctrl+C, copy for ticket, B, Alt+N, next/prev match, F2 (column), Esc (log selection). Global: undo/redo, find, zoom, toggles, Ctrl+0..5, Alt+Arrow.

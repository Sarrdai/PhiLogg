- **feat: text files are one plain-text file node with an editor as Context, a text-mode Filtered view, and a fast virtualized editor (2026-10-01, person-requested)**
  - **One node instead of viewer + copy.** `.txt`/`.json`/`.xml` (ZIP entry, watched folder, loose file) load through the normal path as one file node pinned to the Plain text format (`formatIdForLoad`, `node.textSyntax`). The inline text viewer, its toolbar (Pretty Print, Wrap, "Filter lines"), `inlineViewerDisplayedText`, the nested "text version" node and `node.viewerSource` are gone; image viewers stay. No migration: saved text-viewer records are ignored and swept on restore (below 1.0.0).
  - **JSON layout.** Valid JSON opens pretty-printed by default (`textLayout` `"pretty"`, the file's own text on `textRaw`; invalid JSON loads raw); a Pretty/Raw toggle in the Context toolbar re-parses the node in place (filters kept and recomputed). `textSyntax`/`textLayout`/`textRaw` are carried by the session cache, undo/clone/snapshot and session export/import.
  - **Filtered text mode.** For a plain-text root the Filtered view swaps the log columns for a shared header bar ("Line | <file>") and fixed-height `.text-row`s (line-number column + fold slot + message, the log view's separator lines kept as an inset shadow) with JSON/XML colors; the Entry detail panel is hidden for plain-text files (`body.text-root`).
  - **Editor as Context.** Context shows the whole file as numbered lines (no gap strips): JSON/XML folding, free selection and copy rebuilt from the line model (folded lines included; Ctrl+A in the editor selects the whole file through the model), hit lines and text matches of the active filter marked, reveal/jump from Filtered or the minimap, the find bar searching and marking the editor's lines ("Add as filter" included), Wrap shared with the Filtered rows, and a Context<->Filtered tab switch that keeps the topmost line in place. A file node starts on Context, other nodes on their usual view.
  - **Virtualized.** Only the lines in/near the viewport are in the DOM (model with `vis`/`tops`, one frame per scroll); DOM identity is preserved across renders, selection endpoints are pinned while scrolling away. Measured in headless Chromium on a 19.3 MB / 393,601-line simulator file: the old viewer took 23-33 s to show it; now Context is painted ~945 ms and Filtered ~872 ms after load, tab switches take 33-46 ms, scrolling keeps a 16.7 ms median frame with ~54-76 DOM rows.
  - **Simulator.** `tools/log-sim` gained the `jsondoc` and `xmldoc` formats (GROUP 300) for JSON/XML documents.
  - **Tests**: new Groups 347-351 (load path and layouts, Filtered text mode, editor as Context, find bar, virtualized editor incl. Ctrl+A); the text-viewer groups were rewritten or removed.

- **refactor: a filter-node field is now one table row instead of a dozen hand-written copies (2026-10-02, code review)**
  - Filter JSON, the filter library and the session cache share one serializer (`serializeFilterNodeFields`), one materializer (`materializeFilterNode`) and one validity rule (`serializedFilterNodeValid`); copy/paste and undo/redo copy through the same table, `FILTER_NODE_FIELDS`. Written files and cache records are byte-identical to before. The session-cache loader now also drops an and/or/link node without baked sides, as the JSON import always did.
  - GROUP filter-node-carriers round-trips every filter type through all four carriers and fails for a node property no carrier knows, so the "thread a new field through all carriers" rule is enforced instead of remembered. Not carried by any: `locked`, `collapsed`, `selectionOrdinal` (a pasted/undone/reloaded Selection N node loses its ordinal — left as is).
  - **Tests**: GROUP filter-node-carriers. Docs: PROJECT.md "Known gotchas", docs/filters.md, docs/persistence-and-sync.md.

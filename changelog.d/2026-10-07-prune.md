- **feat: "Prune file to this result…" drops everything outside a filter's result (2026-10-07, person-requested)**
  - A filter node's context menu offers it; after a confirmation dialog the root file keeps only that result in memory (not undoable, reopen the file to get the rest back). Other filters recompute, bookmarks/notes of dropped entries go.
  - Cuts are marked: a non-clickable "N entries pruned" strip in the Context view, a dashed boundary line plus gutter icon in the Filtered view of the file node, a pruned file icon/tooltip. Survives reload and session export (embedded log).
  - Measured (headless Chromium, 650k-entry file, filter keeping 171,202): JS heap after GC 303 MB to 91 MB, prune 381 ms.
